# ADR-022 边缘限流与 CC：节点本地优先，Redis 永不在请求路径上（P4 预案）

- 状态：已接受（预案；架构代理非交互决策）｜日期：2026-11-16｜关联：基线 §13.2、§13.3；PRD FR-98、FR-99、R-9、FR-101、FR-66；architecture AD-22｜阶段：P4

> **预案，进入该阶段前须 PoC 复核。** 数值（窗口、阈值、字典大小）均为配置，默认值待基线测试后确定。

## 背景

基线 §13.2：CC 含单 IP、IP+URI、API 路径、站点整体限速、临时封禁、JS Challenge、CAPTCHA、观察模式、规则例外；**边缘限流必须避免 Redis 成为每次请求的强制远程依赖**。PRD R-9：本地限流为主，跨节点汇总异步，跨节点总量为近似值，Redis 故障时限流降级为本地。限速在规则引擎的 `waf_cc` 阶段执行（ADR-005，阶段 3，P4 前为空阶段但位置保留）。

## 决策

1. **计数在节点本地**：`lua_shared_dict`（容量配置项）存放限速状态。算法：固定窗口 + 滑动近似（两窗口加权）或令牌桶，按规则选择；键 = `site_id:rule_id:<维度值>`，维度为 IP、IP+规范化 URI、API 路径模板、站点整体。**请求路径上只访问本地共享内存**，不访问 Redis/MySQL/Server。
2. **内存有界**：共享字典满时按 LRU 淘汰；溢出行为按规则配置 `fail_open`（默认，放行并记 `LIMIT_DICT_PRESSURE` 事件）或 `fail_closed`（仅对显式高风险规则）。字典压力指标上报监控。
3. **跨节点汇总异步**：Agent 周期读取本地命中计数，经 `TelemetryService.ReportEvents/ReportRollups` 上报；Server 聚合后**不要求精确全局配额**。需要跨节点效果的能力仅限：(a) **临时封禁名单**由 Server（或 Agent 本地检测）生成，经 `desired` 运行期数据通道（与 ADR-007 的运行期标记同一机制）下发到各节点，有 TTL；(b) 告警/统计。声明：**跨节点总限额为近似值，不提供精确全局配额**（R-9）。
4. **Redis 角色**：不参与数据面。Server 侧（Console/Admin API 限流、登录节流）可用 Redis（ADR-025）；与边缘限流互不依赖。Redis/主控故障时边缘限流**照常工作**（FR-98 可验证项）。
5. **挑战与观察模式**：JS Challenge/CAPTCHA 的状态用签名 Cookie（HMAC，密钥由集群级配置经修订的 `global` 块外的运行期密钥分发，实现时与 ADR-011 对齐），不依赖服务端会话存储；CAPTCHA 提供方为插件接口（P4 评估）。**观察模式**只记录不阻断，事件字段标注 `mode=observe`；**规则例外**（按路径/IP/Header）在 `waf_cc` 阶段前置求值。
6. **执行位置与顺序**：`real_ip`（由 Lua 引擎 `le.realip.resolve` 计算出可信客户端 IP，存入 `ngx.var.le_client_ip`，ADR-006 §1；不再使用 nginx realip 模块）→ `access_control` → `waf_cc`（限速在此）；限速判定使用可信客户端 IP，防止 XFF 伪造绕过（ADR-006）。
7. **事件上报**：命中事件进入 `security_events`（采样/聚合以防事件风暴，策略 PoC 决定），日志脱敏（NFR-12）。
8. **声明**：CC/限速不等于 L3/L4 DDoS 清洗（FR-101），官网/Docs/Console 须含边界声明。

## Binds / Prevents / Rule

- 约束：Lua 引擎 `waf_cc` 阶段实现、Agent 的运行期通道与上报、规则 DSL 的 `rate_limit` 类型、security 模块。
- 防止：每请求依赖 Redis/Server 导致延迟与故障放大；以精确全局配额的虚假承诺；内存无界增长。
- 规则（AD-22）：**边缘限流本地优先，Redis 永不在请求路径上；跨节点总量为近似值。**

## 备选方案与权衡

- **Redis 集中式限流（INCR + EXPIRE/Lua）**：否决——违反基线硬性条款；每请求远程往返增加延迟，Redis 故障时要么放行要么全断。
- **每请求调用 Server 判定**：否决——同上且更重。
- **一致性哈希把同一 IP 路由到固定节点以获得精确计数**：否决——需 DNS/L4 层配合，超出 P4 范围，且破坏调度自由度。
- **仅用 nginx `limit_req`/`limit_conn`**：部分采纳——对站点整体粗粒度可用；但动态维度（IP+URI 模板）、封禁、观察模式需要 Lua；统一由引擎执行以保持规则模型一致。

## 后果

- 单节点视角的限额：N 个节点时总放行量可达 N × 单节点限额（近似），需在文档如实说明。
- 共享字典大小与淘汰策略影响攻击下的行为，需基线压测确定。
- 临时封禁下发有传播延迟（心跳间隔量级）。

## 可被推翻处

若用户要求精确全局配额：只能引入「同步配额服务」并接受其延迟/可用性代价，且必须设计为可旁路的**异步预取令牌**（节点批量向 Server 申请令牌额度），仍不得每请求远程调用；影响 FR-98 与本 ADR。

## 验证

- 断开 Redis 与主控后限流仍在节点生效，且请求延迟无显著恶化（以基线对比；阈值待定）；
- 共享字典压满的行为（fail_open 记录事件）测试；观察模式仅记录；例外规则绕过；挑战通过后有效期内不重复挑战；
- Lua 引擎在 Linux + OpenResty 上验证，缺环境标「等待环境验证」（ADR-023）；WAF 误拦截测试沿用基线 §23。
