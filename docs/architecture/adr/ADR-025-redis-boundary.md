# ADR-025 Redis 使用边界：非唯一真相源，丢失只降级

- 状态：已接受（架构代理非交互决策）｜日期：2026-11-16｜关联：基线 §2.1、§13.2；PRD R-9、FR-98、FR-17、FR-29；architecture AD-25、F-11｜阶段：M1

## 背景

基线技术栈固定 Redis 8（实现客户端 go-redis/v9，2026-11-16 查询版本 v9.23.0，实现时核对），但同时要求边缘限流不得依赖 Redis（§13.2）、数据面在主控离线时继续服务（§3.1）。若 Redis 被当成事实来源（会话、任务、锁、计费），其丢失/重启/驱逐会造成数据丢失或停服。需要明确 Redis 能做什么、不能做什么、不可用时怎么办。本机 Redis 为 8.10.1；是否开启持久化（AOF/RDB）不作为正确性前提。

## 决策

1. **Redis 只存可重建/可丢失的数据**，用途清单（穷尽）：
   - **限流与节流计数**：Server API 限流（用户/Token/IP）、登录节流（ADR-018）；
   - **读缓存**：已验证会话缓存（TTL≤60s）、权限集缓存、`public/stats` 等短期聚合；
   - **失效广播**：`permission_version` 变更、缓存清除的 Pub/Sub；**节点证书吊销缓存失效**（ADR-003 §6，Redis 不可用时短 TTL 轮询 MySQL）；
   - **任务唤醒**：新任务入队通知（ADR-019），仅「唤醒」；
   - **短期去重/撤销缓存**：如告警去重窗口的加速层、webhook 重放窗口、预览链接撤销状态的缓存（权威记录在 MySQL `website_preview_links`；预览令牌改为不透明令牌 + 库存哈希，不再有 `jti` 黑名单，ADR-015）。
2. **真相源永远在 MySQL**：会话（`sessions`）、任务与队列（`tasks`）、租约与锁（`job_locks`）、幂等键（`idempotency_keys`）、计量/钱包/账单、审计均落 MySQL。**Redis 不存分布式锁的唯一副本、不存任务队列的唯一副本、不存任何计费或授权的唯一状态。**
3. **数据面零依赖**：OpenResty/Agent 的请求路径不访问 Redis（ADR-022、ADR-020）。Node 与 Redis 之间**无直连**。
4. **键空间规范（全系统唯一命名）**：`le:<env>:<模块>:<用途>:<标识>`，其中 **`<env>` 是环境名占位符，实际键不含花括号**（旧文 `le:{env}:…` 的花括号在 Redis Cluster 下会被当作 hash tag，MIN-06）；租户相关键在“标识”前加租户段 `t<tenant_uid>`，如 `le:prod:rl:api:t01H…:<token_prefix>`（ADR-009 §10 不再使用独立的 `t:<tenant_uid>:` 前缀）；**所有键必须设置 TTL**（唯一例外需在代码评审中登记）；值不含明文敏感信息（令牌只存哈希或不存）。租户键读写经带 `Scope` 的封装（ADR-009）。
5. **降级矩阵**（Redis 不可用/被清空时）：
   | 功能 | 降级行为 |
   |---|---|
   | API/登录限流 | 回退到进程内限流 + DB 兜底（`users.failed_login_count/locked_until`），可能略宽松，记录告警 |
   | 会话/权限校验 | 直接读 MySQL（延迟上升，结果正确） |
   | 任务唤醒 | Worker 按轮询间隔领取，任务不丢（ADR-019） |
   | 失效广播丢失 | 缓存依赖短 TTL 自然过期；`permission_version` 变更在 TTL 内最终生效 |
   | 告警去重 | 回退到 MySQL 中的告警状态（`alert_events`），可能多发一条，不会漏发恢复通知 |
   | 边缘限流/CC | 不受影响（节点本地） |
6. **Pub/Sub 视为有损**：任何依赖广播的消费者必须同时有「轮询/TTL 兜底」；不得假定消息必达。
7. **持久化与淘汰策略不作为正确性前提**：部署文档建议 `maxmemory-policy` 设为 `volatile-lru`/`allkeys-lru` 之一（具体值实现时核对），但即使数据被清空系统仍须正确。
8. **启动与健康**：Server 启动时 Redis 不可达**不阻止启动**（以降级模式运行并告警）；`/healthz/ready` 报告 Redis 状态为 `degraded` 而非失败（是否因 Redis 失败而拒绝就绪由配置项决定，默认不拒绝）。安装期：Tools 仅做连通性探测（不可达只警告），Server 安装向导负责 Redis 配置并校验主版本 ≥8（tools-design §13）；**运行期**的 Redis 中断则按降级矩阵处理。
9. **版本与特性**：仅依赖 Redis 通用命令（字符串/哈希/过期/Pub/Sub/Lua 脚本可选）；不依赖 Redis 8 的新增模块能力，避免与 Redis 兼容实现或旧运维环境绑定；Redis 8 为基线版本，**最低版本约束实现时核对**。

## Binds / Prevents / Rule

- 约束：所有使用 Redis 的 Server 模块（auth、monitoring、task 运行时、notification）、部署文档、Tools 安装检查。
- 防止：把 Redis 当数据库造成数据丢失；Redis 故障引发 Server 停服或边缘停服；跨租户键污染。
- 规则（AD-25）：**Redis 不是唯一真相源；丢失 Redis 只降级不丢数据；键必有 TTL；数据面永不依赖 Redis。**

## 备选方案与权衡

- **Redis 作会话存储（唯一）**：否决——重启/驱逐导致全员登出且无法审计吊销；改为 MySQL 真相 + Redis 缓存。
- **Redis 作任务队列与分布式锁（Redlock 类）**：否决——无围栏、故障语义复杂；MySQL 租约 + 围栏更可证明正确（ADR-019）。
- **完全不用 Redis**：否决——基线固定使用 Redis 8，且限流/缓存/广播确有收益；只需限定边界。
- **要求 Redis 必须持久化 + 哨兵/集群高可用**：否决（M1）——抬高运维成本；用「降级而非依赖」更契合单机宝塔部署，高可用可由运营者自行选择。

## 后果

- 降级路径带来额外实现与测试成本（每个 Redis 使用点都需要回退分支）。
- Redis 故障期间限流变宽松、延迟升高，需监控与告警（`degraded` 指标）。
- 键 TTL 约束需 lint/评审保证（可在封装层强制：封装函数不允许无 TTL 的写入）。

## 可被推翻处

若用户希望 Redis 承担更多（如会话唯一存储以降低 DB 压力）：须接受其丢失即登出并提供持久化要求，更新 ADR-018 与部署文档；任务/锁/计费不建议改动。

## 验证

- 故障注入：停止/清空 Redis，验证登录节流、会话校验、任务领取、告警去重按降级矩阵工作且数据不丢（含 Redis 重启后的缓存重建）。
- 静态检查：Redis 封装层拒绝无 TTL 写入；Node/Agent/OpenResty 代码中无 Redis 依赖（依赖方向检查，ADR-001）。
- 集成：`/healthz/ready` 在 Redis 不可用时返回 `degraded`；边缘限流在 Redis 断开下继续生效（FR-98、AC-G-7）。
