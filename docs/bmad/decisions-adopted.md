# 已采纳的默认决策汇总

> 依据用户「完全自主、仅在重大分叉/破坏性操作/严重矛盾时打断」的偏好，`epics.md` 的全部待用户决策项（UD）已于 2026-11-16 **逐项复核默认值并采纳**；本表记录采纳的默认值、复核结论，以及**一旦被用户推翻会波及的范围**。推翻任一项时：改本表对应行 + `epics.md` 的 UD 行与受影响 Story，必要时走 `bmad-correct-course`；已完成 Story 的返工量见「推翻影响」列。
>
> 复核口径：① 默认值与基线 `LINGEDGE_V2_REQUIREMENTS.md`、PRD、架构（2026-11-16 修订后）无冲突；② 不含虚构数值（待基线测试的参数不预设）；③ 不降低安全/验收标准；④ 默认值下开发可继续。
>
> 图例：**采纳**＝按 `epics.md` 默认值采纳；**采纳（修订）**＝默认值经复核后有调整；**采纳（临时）**＝无原始默认值，采纳一个不引入返工的临时处置。

## 4. 复核中发现并已纠正的规划缺陷（供审阅）

以下为本次对照修订日志复核时发现 `epics.md` 与修订后上游冲突、已就地纠正的项（不属 UD，不需用户决策）：

1. 审计写入语义：`1.21` 原写「审计失败不阻断业务」，与 database/README §5.1「审计与业务同事务」冲突 → 改为同事务、失败即整体回滚（fail-closed）。
2. 租户可见 `GET /available-clusters`（`3.35`）与修订日志「不采纳」冲突 → 删除，向导无集群选择。
3. 调试请求「回环临时回显源站」（`3.32`）已被 ctl 封闭操作 `debug_simulate` 取代 → 改写，SSRF 无需豁免。
4. 节点升级结果文件目录（`3.34`）原写 `/var/lib/lingedge/tools/node-upgrade/` → 改为定稿的 `/var/lib/lingedge-node-upgrade/`；`--apply-staged` 无路径参数。
5. Server metrics 端口 9100 → 9180（`1.12`、`1.35`）；`doctor` 节点证书告警阈值 1/3 → <1/6（`1.42`）；enroll 错误码统一为 `enroll.token_invalid`（`3.33`）；Redis 键名去花括号（`1.10`）。
6. 迁移分段：证书表前移到 1.8，`node_tasks` 等新表归位；1.7/1.8/1.9 的表集合与文件范围随 database/README §8.1 重排（61 张 M1 表）。
7. KCR 的「warning/error 二选一」（`3.6`、`3.26`）统一为发布失败（默认）或规则显式 `cache_interaction=bypass`。
8. 新增 Story 3.51（发布编排队列）与 3.52（节点级回滚 `held_seq`），把原 3.11/3.12 中无法在单会话内完成的编排与回滚载体独立出来。

## 5. 推翻流程

1. 用户给出新决策 → 更新本表对应行（编号、默认值、复核结论、影响）。
2. 同步 `epics.md` 的 UD 行与受影响 Story 的 AC；若涉及契约（OpenAPI/proto/迁移）则按 ADR-017 §10 走变更说明与 `contract-changes/`。
3. 已完成 Story 的返工以「推翻影响」列为准；如涉及已冻结契约（CF-1…CF-9），先用 `bmad-correct-course` 出变更提案。
