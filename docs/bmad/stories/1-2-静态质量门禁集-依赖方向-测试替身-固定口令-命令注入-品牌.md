## Intent

**Problem:** 硬性规则（模块依赖方向、测试替身隔离、无固定口令、无 shell 拼接、品牌）目前只写在文档里，违规代码仍可合并；`make lint` 只有 gofmt/vet，`make security` 是 `NOT_IMPLEMENTED(story 1.2)`。

**Approach:** 在 CI/本地入口机械强制这些规则：golangci-lint（depguard 依赖方向、forbidigo 禁 exec）+ 一个仅依赖标准库的门禁程序 `scripts/gates`（依赖图规格 → 生成 depguard 配置、结构检查、测试替身反向检查、固定口令/品牌/shell 扫描）；每条规则有「正向通过 + 负向必败」自测，负向样例只存在于临时副本。

## Boundaries & Constraints

**Always:** 外部工具以 `go run <pkg>@<固定版本>` 调用且版本可验证；depguard 规则据 ADR-001 依赖图机械生成，不设「临时豁免」；`internal/platform/ports` 仅接口与 DTO；门禁失败即非零退出；未实现的其余安全门禁（G-1…G-5、G-7…G-10、G-13）如实标注未接入。

**Never:** Docker/Compose/K8s 任何文件；git commit（本次调用方禁止）；改动 `SmartCDN` 目录；负向样例残留在仓库；在生产代码中加入「检测到测试环境」分支；引入第三方 Go 依赖到 `go.mod`；虚构门禁通过。

### 决策与偏差

- **工具与版本（均已在本机实测，非虚构）**：golangci-lint **v2.15.0**（`go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.15.0`，`version` 输出 `built with go1.27.1`）；govulncheck **v1.9.0**（`go run golang.org/x/vuln/cmd/govulncheck@v1.9.0`，`make vuln` 无受影响漏洞）。均不进 `go.mod`（`go.sum` 仍为空文件、无第三方依赖）。depguard、forbidigo、errcheck、staticcheck 等内置于 golangci-lint，未另装 go-arch-lint（二选一，取 depguard）。
- **依赖方向规则机械生成**：`scripts/gates/spec.go` 是 ADR-001 §3–§7/architecture §5.3 的唯一机器可读来源，`make gen-lint` 生成 `.golangci.yml`（约 1400 行，含 23 个模块 + tools + pkg + cmd 规则），`make arch-check` 校验无漂移；不设任何「临时豁免」。`${base-path}` 占位符锚定路径（实测 golangci-lint v2.15.0 支持），避免 `**/pkg/**` 在仓库位于含 `pkg` 的目录时误匹配全部文件。
- **ports 的取舍**：本 Story 只建立 `internal/platform/ports` 包骨架（`doc.go`）与结构门禁（仅接口与 DTO、无函数/变量/别名、接口名限于 ADR-001 §5 清单的 11 个）。各接口的方法集属于其拥有者 Story（node/cache/…），此处不臆造签名。
- **forbidigo 范围**：`os/exec`、`syscall.Exec/ForkExec/CreateProcess`、`os.StartProcess`、`unix.Exec` 一律禁止，白名单入口仅 `internal/tools/security`；`scripts/`、`_test.go`、`tests/` 不进发行产物，豁免 forbidigo（`gates shell` 对 `scripts/` 与生产代码仍生效；`tests/` 与 `_test.go` 不受 shell 门禁约束，已知并接受）。`internal/tools/security` 虽可用 exec，但 `gates shell` 仍禁止 shell 解释器、命令名拼接/变量/含空白。
- **测试替身门禁**：源码层（位置、构建标签求值、生产代码引用/embed fixtures/`testing.Testing()`、假数据标记 `scripts/gates/data/fake-data-markers.txt`）+ 构建层（对 3 个发行目标做 `go list -deps`；宿主平台构建未剥离产物后查 `go tool nm`、`go version -m`、字符串标记）。depguard 另禁生产代码 import `testing`/`httptest`/testify/gomock/sqlmock/miniredis。lint 的 `run.build-tags` 含 `lingedge_testdouble`，使替身包同样受静态规则约束。
- **固定口令/品牌/shell 门禁**：均为仅标准库的 Go 程序，自身目录 `scripts/gates` 被扫描类门禁跳过（规则文本会命中自身）；测试用例的违规样例在 `tests/gates` 中运行时拼接，避免仓库自身触发门禁。口令 allowlist 仅 `tests/fixtures/` 且文件含「仅测试」。品牌：词表 `smart[-_ ]?cdn`、`chat[-_ ]?sphere`；`docs/` 中带明确隔离措辞（隔离/不触碰/外部项目名…）的行豁免，现有 4 处文档引用均属此类，代码/配置/README 一律不豁免。
- **`make security` 语义**：由 `NOT_IMPLEMENTED(story 1.2)` 改为真实目标，只覆盖 G-6/G-11/G-12/品牌，输出中明示未接入的 G-1…G-5、G-7…G-10、G-13；`tests/scaffold` 相应更新（`security` 不再是占位，并新增 `TestMakefileWiresGates` 断言接线）。
- **顺带修复**：新 errcheck 发现 `pkg/version` 未检查写错误（`fmt.Fprintln/Fprintf`），已修（行为不变，stdout 写失败返回 1）。
- **未创建 git 提交**：按调用方要求。1.1 的 AC7（首个提交）仍待授权，本 Story 无提交 AC。
- **CI**：新增 `.github/workflows/ci.yml`（action 以提交 SHA 固定，checkout v7.0.1、setup-go v7.0.0，已用 `git ls-remote` 核对为提交而非 tag 对象）。**尚未在远端实际运行**（无远端/提交），标「等待环境验证」；分支保护（必选状态检查）亦属托管侧设置，未配置。

### 实际验证（本机 macOS arm64、go1.27.1）

- `make lint`（vet ×2〔含 `-tags lingedge_testdouble`〕、gofmt、scaffold、`gates arch`、golangci-lint `0 issues`、`gates shell`）→ 通过。
- `make security`（testdouble / passwords / brand / shell 四项门禁）→ 通过；构建层实际编译 7 个 cmd 并扫描符号与字符串。
- `make gate-selftest` → `scripts/gates` 单测（约 100 个子用例）+ `tests/gates` 三个端到端自测全部通过；`make test`、`make race`（`-race`）→ 通过；`make build && make verify-build` → 15 个产物 ok；`make vuln` → 无受影响漏洞。
- **负向样例（均在临时副本中写入，用后自动删除，仓库无残留，已用 `find` 复核）**：
  - 依赖方向（golangci-lint/depguard，一次运行 13 个违规全部命中、12 个合法写法零误伤）：`node→certificate`（L2）、`cmd/lingedge-node→tenant`、`tools→auth`、`origin→cache`（L2↔L2）、`cache→node`、`website→origin`（上行）、`platform→website`、`pkg→internal/platform`、`cmd/lingedge-server→tools`、`cmd/lingedge→node`、生产代码 import `testing`、`os/exec`（含别名/Context）、`syscall.Exec`、`os.StartProcess`；合法：经 `platform/ports` 的调用、`origin→website`、`website→tenant`、`reporter→monitoring`、装配层 import 多模块、`tools/security` 内 `exec.Command("systemctl", …)`、带标签替身包 import `testing`、`_test.go` 使用 exec。
  - 模块 A import 模块 B 的 `internal/<B>/internal/service`：`go build` 失败（`use of internal package … not allowed`）；合法的自有实现包引用与根包 import 通过。
  - 测试替身：无标签替身包被 cmd 引用 → `go list -deps` 命中；常量折叠产生的 `fake-traffic` 仅在产物字符串中出现 → 产物扫描命中；源码假数据标记、否定/或构建标签、位置非法等单测。
  - 固定口令（代码/配置模板/迁移/无引号 env/DSN 等）、品牌（代码/配置/README/路径/docs 非隔离引用）、shell（`sh -c`、`exec.Command("sh","-c",…)`、命令名拼接/变量/dot-import、systemd unit）各有负向用例，清理样例后门禁恢复通过。
  - 门禁配置漂移：手工改 `.golangci.yml`（模拟临时豁免）→ `gen-lint -check` 失败。
