## Intent

**Problem:** 含 `token:manage` 的权限集写入 Redis 缓存（`le:<env>:auth:perms:*`）时，`redisx` 的写入门禁 `redact.String(value) != value` 把 JSON 里的 `"token:manage"` 读成「键名 token、分隔符 `:`、值 manage」而判为敏感，`GetOrLoad` 只能跳过回填：每个请求一条 warn「缓存值含敏感信息，已跳过回填（编程错误）」并回库。结果正确，但丢了缓存且日志有噪声。

**Approach:** 权限码缓存是「非机密的结构化数据」，不应走字符串启发式。在 `redisx` 新增**调用方提供的 `StructuredGuard`（schema 白名单）写入路径**（`Client.SetStructured` / `Cache.GetOrLoadStructured`），权限缓存改走它；**不修改 `pkg/redact`、不修改 `Set`/`GetOrLoad` 的 redact 门禁**，G-5/G-6 不放宽。

## 复现（先失败）

`tests/integration/auth/permcache_sensitive_test.go::TestPermCacheBackfillsEvenWithRedactLookalikeCodes`（真实 server 栈 + 临时 MySQL + 临时 redis-server + 真实 redact）在修复前失败：`含 token:manage 的权限集应已回填 Redis`。

## 被误判的权限码（枚举 `rbac.All()` 共 81 个，逐个对其缓存 JSON 形态跑 `redact.String`）

| 权限码 | 命中规则 |
|---|---|
| `token:manage` | 键头含 `token` 后跟 `:` |
| `credential:read` | 键头含 `credential` 后跟 `:` |
| `credential:write` | 同上 |

其余 78 个（含 `cms:*`、`cache:disk:read`、`metrics:platform:read`、`login-log:read` 等）不受影响；**目录中没有 `secret:*`、`key:*`、`password:*` 形态的权限码**（`secret:rotate`、`key:manage` 不存在，守卫测试里作为「目录外」负向用例）。内置角色码与菜单键不含冒号，不受影响。

## 修复与取舍

- `redisx.StructuredGuard func(value string) error`：**替换**（不叠加）redact 启发式；nil 守卫 fail-closed（`ErrSensitiveValue`）；守卫拒绝同样返回 `ErrSensitiveValue`，不发任何命令，仍要求正 TTL 与合规键。
- `service.permEntryGuard`（perms.go）：严格白名单——单个 JSON 对象、`DisallowUnknownFields`（只允许 p/r/m/v）、无尾随内容；`p` 每项必须是 `rbac.Known` 的权限码；`r` 须符合 `reRoleCode` 且 `redact.String` 逐项不变；`m` 须符合菜单键语法且 `redact.String` 逐项不变。拒绝原因不回显内容。
- 取舍一：没有采用「给 redact 加权限码形态豁免」——那会在全局脱敏引擎里开口子，且 `redact` 是 Server/Tools/Node 共用的最后一道防线；把例外限定在「调用方声明的 schema + 目录」更窄。
- 取舍二：守卫比启发式**更窄**（只放行已知形态），但 `r`/`m` 的语法允许小写字母数字串，此类形状（如 43 位小写字母数字角色码）与以前一样不会被识别为密钥（redact 的裸密钥规则要求三类字符齐全）——角色码本就是库里的非机密标识，无回归。
- 未知权限码（库里有而目录没有）不会被缓存，仍 warn+回库（fail-closed）；`perms-check` 门禁保证目录与种子一致。

## 测试

- `tests/integration/auth/permcache_sensitive_test.go`：回填成功、TTL≤60s、无 warn、命中缓存；权限变更后旧键清除、新版本再回填、`/auth/me` 一致。
- `tests/integration/redis/redis_test.go::TestStructuredCacheGuard`（真实 Redis）：回填/命中/失效重建/无 warn；守卫拒绝不写入；nil 守卫 fail-closed；普通 `Set` 仍拒绝 `token:manage` JSON（证明 redact 门禁未动）。
- `internal/auth/internal/service/perms_guard_test.go`：整个目录每个权限码单独与整体通过；22 个负向用例（API Token、Bearer、PEM、裸密钥、口令键值、目录外码、额外字段、尾随内容、非 JSON…）全部被拒；`redact.String` 对这些字串在自由文本中仍遮蔽。
- 既有 `TestPermissionChangeTakesEffect`、`TestPermCachePubSubAndPollFallback`、`TestPermCacheTTLBackstop` 与 `tests/security/logscan*` 未改动且通过。
