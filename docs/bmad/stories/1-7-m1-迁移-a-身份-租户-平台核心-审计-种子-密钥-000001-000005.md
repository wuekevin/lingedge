## Intent

**Problem:** Story 1.6 交付了迁移框架，但 `migrations/` 里没有任何真实迁移（13 个迁移的唯一材料是 `docs/database/verification/m1-fk-skeleton.sql` 的规则验证骨架，只保留约束相关列）。上层模块（认证、RBAC、租户、审计、任务运行时、密钥）没有稳定的表结构、权限字典与内置角色可依赖；「`lingedge_app` 逐表授权」「租户表索引以 `tenant_id` 打头」「无 ENUM/浮点/TIMESTAMP」等数据库约定只存在于文档里，没有任何东西强制。

**Approach:** 把 database/README §8.1 的前五个迁移写成真实可发行的 SQL（000001 `identity_core` 12 表、000002 `platform_core` 7 表、000003 `audit_logs`、000004 `seed_builtin` 仅 DML、000005 `keys_credentials`，合计 21 表，全部 `expand`），按各表文档的完整列落库并逐表授权；在 1.6 的 lint 框架里追加 schema lint（AC2）；用真实 MySQL 上的专项测试验证空库 up、重放幂等、约束/外键/CHECK/租户隔离负向、`lingedge_app`/`lingedge_maint` 最小权限负向，并对真实迁移文本做变异以证明三类 DDL 陷阱的预检覆盖。

## Boundaries & Constraints

**Always:** 迁移经 `lingedge_migrate` 账号执行；全部 `expand`、可重入；种子仅 DML 且不含任何口令/哈希、不创建任何用户（管理员只由安装向导创建，G-6）；所有指向 `tenants(id)` 的外键 `RESTRICT`；T? 表用 VIRTUAL 生成列保证平台级唯一；分区表无外键且含 `pmax`；权限字典以 OpenAPI `x-permissions` 与 `TaskType` 为事实源；SQL 参数化；测试用独立临时 mysqld 实例，用后关闭并删除；未能验证的环境项如实标「等待环境验证」。

**Never:** 触碰本机常驻 MySQL 实例（PID 25651/25755）；Docker；Mock 冒充生产；修改 `contract-v1` 已冻结内容（OpenAPI / proto / 已发布迁移 / `docs/database/verification`）；封存（`migrations-seal`）000001–000005（CF-2 才登记）；越界实现 Story 1.8/1.9 的表；push；改 `git config`；改动 `SmartCDN`。

### 范围决策与偏差

- **与 contract-v1 骨架的关系**：1.6 记录已指出 `migrations/` 此前为空（只有 `CHECKSUMS` 与 `embed.go`）；骨架 `m1-fk-skeleton.sql` 只保留约束相关列。本 Story 因此不是「把骨架纳入框架」，而是**按各表文档的完整列写真实迁移**，骨架只作为外键顺序与 DDL 规则的参照（`docs/database/verification` 未改动）。1.6 的骨架 13 文件重放测试保持原样（仅为新增的 schema lint 在骨架替身上补「跨租户索引豁免」注释，见下）。
- **不封存**：`migrations/CHECKSUMS` 未追加（CHECKSUMS 头注释：000001–000013 在 CF-2 冻结时登记）；`make contract-check` 的 `migrations-check` 仍为「已发布迁移 0 个」。因此在 CF-2 之前，若评审发现 000001–000005 的问题可直接修改文件。
- **schema lint（AC2）落点与两处文档张力**：规则放在 1.6 的 lint 框架（`schemalint.go`，随 `Checker` 累积跨迁移的租户表模型）。落地租户索引约定时发现文档自身的张力：README §2.6「所有索引以 `tenant_id` 打头」与 `tenant_members` 必须有「按用户反查所属租户」的 `idx_tenant_members_user(user_id)`（也支撑外键 `fk_tenant_members_users`），以及后续 `site_domains.active_hostname` 这类**必须跨租户唯一**的索引冲突。处置：规则只约束 `tenant_id NOT NULL` 的租户表；主键与「仅含 `uid` 的唯一索引」免判（C1 资源按 uid 解析，§2.3）；其余例外须在语句前写 `-- lingedge:cross-tenant-index=<索引名> <原因>`（原因必填，评审可见）。外键自动建立的支撑索引（索引名=外键名，不在迁移文本里）不受限，真实库断言同样豁免。租户范围表登记清单 `tenantTables`（14 张）要求含 `tenant_id NOT NULL`。该机制对 1.8/1.9 同样适用。
- **权限字典与角色（AC1/AC3 未给细节处）**：字典 = OpenAPI 全部 80 项 `x-permissions` + `tenant:impersonate`（81 项，含 P2–P5 阶段的权限串，仅字典，功能随阶段启用）；`scope` 由 operation 的 `x-tenant-scope` 推导（仅 platform 路由 = `platform`（37，另加 `tenant:impersonate` 共 38）；仅 tenant 路由 = `tenant`（10）；被 `either` 路由或两类共用 = `both`（33）），测试逐项核对并断言「被 tenant/either 路由使用的权限不得为 platform」（acting-as 规则）。内置角色 6 个（`platform_admin/platform_operator/platform_auditor/tenant_owner/site_operator/tenant_viewer`），均 `tenant_id NULL`；租户角色永不含 platform 权限；`tenant:impersonate` 只授予 `platform_admin` 与 `platform_operator`。权限串中的三段形态（`cms:page:write`、`tenant:member:manage`）按「最后一个冒号」拆成 `resource` 与 `action`。`menu_key` 留空（随 Admin 壳 Story 1.37）；`tenant_quotas`、`system_settings` 不预置行（运行模式/`deploy.lineage` 随 1.22 与安装向导）。Story 1.18 AC2 写「租户角色只能授予 `scope=tenant` 的权限」，而 database 文档与 ADR-018 §8/§10 定义 `both` 可被租户角色持有——本 Story 按后者（`tenant` 与 `both`），需 1.18 对齐措辞。
- **`audit_logs` 初始分区**：`p202611`…`p202712` + `pmax`（15 个）；2026-11 分区同时容纳更早的时间戳；迁移晚于 2027-12 执行时写入落入 `pmax`，由 `partition.maintain`（内部周期作业，1.15）REORGANIZE。
- **`tenants.slug` 的 CHECK 用 `REGEXP_LIKE(…, 'c')`**：骨架与 database 文档写的是不带匹配类型的 `REGEXP_LIKE(slug,'^[a-z0-9]…')`，在 `utf8mb4_0900_ai_ci` 下对大写同样通过（不区分大小写），与「小写字母数字连字符」不符；本迁移加 `'c'`，测试覆盖 `Bad`/`-bad`/`a_b`/空串。
- **`tasks.type` 带 CHECK**：platform-identity §4.1 写「新增类型走 expand：放宽 CHECK」，故落为 25 个 `TaskType` 取值的 CHECK（测试与 OpenAPI 枚举逐值比对，且每个取值都能写入、`shell.exec` 被拒）。
- **只对文档写明「CHECK」的枚举加 CHECK**：`login_logs.event/realm`、`sessions.revoke_reason`、`system_settings.group_name`、`audit_logs.actor_type/result` 等文档没有 CHECK 行、取值易随后续 Story 扩展者不加，避免「放宽 CHECK」在 expand 里被 lint 判为破坏（`DROP CHECK`）而增加后续摩擦。
- **Story 1.6 延后项补齐**：`system_settings` 落库后，runner 以运行记录表为准对账 `schema.latest_class_irreversible_applied`（ADR-016 决策 4）：每次 `up` 结束与 `recover` 补记 applied 之后，记录缺失或落后则写入（自愈，见三路评审）；有真实库回归（expand 不写、被拒绝的升级不写、再次不可逆则更新同一行、误删后下次 up 自愈、recover 路径补写、无 `system_settings` 的库静默跳过）。未补的延后项（`recover --mark-applied`、8.0.16 与 CI 接入）仍照 1.6 记录。
- **运行期账号须先于 `migrate up` 创建**：迁移里的 `GRANT … TO lingedge_app/lingedge_maint` 在账号不存在时失败（ERROR 1410），两个账号由安装向导（Story 1.24）创建；测试在临时实例里预建（同 1.6）。

### 实际验证（本机 macOS arm64、go1.27.4；MySQL 8.0.46 独立临时实例，binlog=ON、`log_bin_trust_function_creators=0`）

- 全部门禁通过：`make lint`（vet×2、gofmt、scaffold、arch、golangci-lint `0 issues`、shell、repo-check）、`make security`、`make gate-selftest`、`make test`、`make race`、`make vuln`（No vulnerabilities found）、`make contract-check`（`migrations-check`：已发布迁移 0 个；`freeze-check OK`）、`make build && make verify-build`、`make migrate-test`。
- **空库 up（AC1）**：`migrate.Runner.Up` 在新建空库上经框架执行 000001–000005，0 错误，恰建出 21 张表（逐名比对）；版本表 1–5；`audit_logs` 分区 15 个（`p202611`…`p202712`、`pmax`）、触发器 2 个；`sessions.reauth_at`、`login_logs.uid`、`task_events.uid`、VIRTUAL/STORED 生成列类型均经 `information_schema` 断言。
- **重放幂等（AC5）**：第二次 `up` 为空操作；把全部迁移的每条语句（含 `CREATE TABLE IF NOT EXISTS`、`DROP TRIGGER IF EXISTS`+`CREATE TRIGGER`、`GRANT`、种子 `INSERT … ON DUPLICATE KEY UPDATE`）直接再执行一遍，库结构/授权签名不变、种子行数不变（81 项权限、6 角色、1 租户、0 用户）；篡改已应用的 000001 被校验和拒绝；`expand` 拒绝回退（`ErrDownNotAllowed`，退出码语义同 1.6）。
- **最小权限负向（AC4，真实 `lingedge_app`/`lingedge_maint` 账号）**：app 对 21 张表恰有 21 条表级授权（`audit_logs` 仅 `Insert,Select`），无任何库级/全局授权；app 对 `audit_logs` 的 UPDATE/DELETE/TRUNCATE/`DROP PARTITION`、对 `users` 的 DROP/ALTER、CREATE TABLE、DROP TRIGGER、读迁移版本表全部 ERROR 1142；maint 仅有 `audit_logs` 的 `Alter,Drop,Select`，能 `REORGANIZE PARTITION pmax` 与 `DROP PARTITION p202611`（旧行随分区消失、不触发行级 DELETE 触发器），对 `DROP TABLE users/tenants`、`DELETE/UPDATE/INSERT audit_logs`、读 `users`、`ALTER users` 全部 ERROR 1142；持有 ALL 的账号 UPDATE/DELETE `audit_logs` 被触发器以 ERROR 1644（`immutable`/`delete forbidden`）拒绝。
- **schema 约定（AC2，真实库 `information_schema`）**：无 enum/set/float/double/decimal/timestamp/time 列；全部 datetime 精度 3；TEXT/JSON/BLOB 无任何默认（含表达式默认）；全 InnoDB、`utf8mb4_0900_ai_ci`、有主键；指向 `tenants` 的 7 个外键全部 `ON DELETE RESTRICT`，无 `ON UPDATE CASCADE/SET NULL`；`audit_logs`/`login_logs`/`event_outbox`/`job_locks` 无外键；租户表（`tenant_members`、`tenant_quotas`）除登记的 `idx_tenant_members_user` 与外键支撑索引外所有索引以 `tenant_id` 打头；**EXPLAIN**（60 租户 × 5 配额的数据量，`ANALYZE TABLE` 后）：带 `tenant_id` 的列表查询走 `uk_tenant_quotas`/`uk_tenant_members`，漏写租户条件则「Table scan」。静态 schema lint 的变异覆盖：对真实迁移文本分别改成 ENUM、TEXT/JSON DEFAULT、TIMESTAMP、`DATETIME` 无精度、DOUBLE、租户表非 tenant_id 打头索引、租户表缺 `NOT NULL tenant_id`、删掉跨租户豁免，lint 全部报出对应规则；另有 56 个负向夹具恰好触发各自规则。
- **约束负向（真实库，事务内回滚隔离）**：users（`user_type/status/邮箱小写/TOTP 须有密钥` 的 CHECK=ERROR 3819、活动邮箱唯一与软删除后复用、`password_hash` 无默认=1364）、tenants（至多一个默认租户=1062、slug 格式 CHECK、超长=1406、owner 外键 SET NULL）、tenant_members/quotas（复合唯一、跨租户同键允许、非法状态/负配额 CHECK、父行缺失=1452、被引用租户删除=1451 RESTRICT、用户删除级联成员）、permissions（scope/`code=resource:action` CHECK、三段权限串）、roles（**NULL 租户下平台角色也唯一**、与种子内置角色冲突=1062、跨租户同名允许、平台角色不得带租户=3819）、user_roles（平台级授予唯一）、role_permissions 级联、sessions（realm CHECK、token 唯一、级联）、api_tokens（前缀/哈希唯一、轮换自引用 SET NULL、`scopes_json` 必填）、login_logs（C2u、无外键）、system_settings（`value_json`/`value_enc` 二选一）、system_installations、tasks（**每个 OpenAPI `TaskType` 都可写入**、`shell.exec`/非法状态/进度>100 被拒、`(type, idempotency_key)` 唯一而 NULL 键不受限、父任务级联、created_by SET NULL）、task_events、job_locks、idempotency_keys（task SET NULL）、event_outbox、signing_keys（**每个 purpose 至多一个 active**、非 active 不受限、轮换后新 active 可建）、audit_logs（无外键、2099 年落入 `pmax` 不报 ERROR 1526、`(uid, created_at)` 唯一）。
- **DDL 陷阱预检覆盖（已知陷阱，真实迁移文本变异）**：① CHECK×FK：`roles` 外键改 `ON DELETE SET NULL` / 加 `ON UPDATE CASCADE` → 静态 `ddl-check-fk` 报出、真实 MySQL ERROR 3823；② 生成列×FK CASCADE：`roles.uniq_key`、`user_roles.tenant_key` 改 STORED 且租户外键改 CASCADE → `ddl-generated-fk`、真实 ERROR 1215；③ 前向外键：`tenants` 先于 `users`、`platform_core` 先于 `identity_core` → `ddl-forward-fk`、真实 ERROR 1824；另 `audit_logs` 加外键 → `ddl-partition-fk`、ERROR 1506；缺 `pmax` → `ddl-partition-pmax`、越界写入 ERROR 1526。对照项：未变异的真实迁移逐条执行 0 错误。
- **种子（AC3）**：库内断言默认租户恰一个且 `is_default=1`、无 owner；`users/sessions/api_tokens/tenant_members/user_roles/signing_keys/…` 全空；`000004` 文本不含 `password/secret/token_hash/totp/identified by` 等，其它迁移不含 `INSERT`；`make security`（G-6 固定口令扫描）通过。权限字典与 OpenAPI 的一致性（OpenAPI 引用的权限必须存在、种子多出的只有 `tenant:impersonate`、scope 与 `x-tenant-scope` 一致）由测试在 CI 守住（Story 1.18 AC1 的 OpenAPI↔种子一致性在此已有一份真实库版本）。
