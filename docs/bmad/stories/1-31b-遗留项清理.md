## Intent

**Problem:** 1.31 交付时登记了三项「本机能做却没做」的限制：站点 vhost 解析不跟随 `include`（宝塔/系统 nginx 的站点多经 `include …/vhost/*.conf` 与 server 内片段组织，漏报同名域名/端口冲突）；MySQL 的 unix socket 端点不探测（宝塔环境常只开 socket）；Node.js 经 nvm 等非固定目录安装时识别不到。用户要求：能在本机测的必须做完、测掉，不丢进遗留。

**Approach:** 全部在 `internal/tools/baota`、`internal/tools/probe` 内追加式完成，**没有新增迁移（000001–000018 不变）、没有 OpenAPI/proto/CF-6/contract-v1 变更、`state.json` 仍是 schema 2（`baota.Report` 无字段增删）、`resolver.System` 无字段变化、没有新增依赖、没有改任何门禁/白名单/lint 配置**。规则全文见 tools-design §11.4 的三段 1.31b 增补。

## 关键行为与约束

- **include**：只读；`Options.Include`（`IncludeOptions`）可替换白名单根与各上限（默认文件 512、字节 8 MiB、深度 16、glob 256、节点 50 万）；相对路径相对主配置所在目录；`Site.File` 为 server 块实际所在文件；站点按「真实文件+server_name+listen」去重；include 的 warning 写入 `Report.Notes`（不新增 `Report` 字段）。
- **socket 凭据信任**：属主是 root、当前用户或 `mysql`/`mariadb`/`redis` 账号才发送凭据，否则 MySQL/Redis 都拒绝发送并说明（测试：服务器端记录收到的全部字节，断言没有口令与 `AUTH`）。
- **不读配置文件找 socket**：`my.cnf`/`redis.conf` 被 readGuard 禁止；「配置声明的 socket」由调用方（Server 向导）经 `Options.MySQL/Redis` 的 `UnixEndpoint` 或 `MySQLSockets/RedisSockets` 提供，其余走候选位置与 `/proc/net/unix`。
- **自动发现的触发**：`MySQLSockets/RedisSockets` 为 nil 且所有 TCP 端点不可达时才探测候选（且只探测存在的 socket）；非 nil（含空切片）= 恰好探测这些路径、不自动发现。

## 与通常做法不同的设计决定

- **Node 不执行未知路径下的二进制**：版本取目录名并以 `node_version.h` 校验。代价：目录被人为改名时可能与真实版本不符——头文件不一致时已以头文件为准并标注来源；若两者都缺失则只有目录名。
- **PATH 上的 node 优先于非固定目录的更高版本**：那才是启动 website 时实际会被执行的；非固定目录安装仍完整列在 `Result.NodeInstalls`，只有 PATH 上没有 node 时才用最高版本填充 `System` 并告警。
- **include 以「include 链」判环而不是全局已访问集合**：宝塔每个站点都 include 同一个 `enable-php-NN.conf`，全局集合会漏掉第二个站点的片段内容；同一文件仍只读一次并缓存，节点总数有上限防指数膨胀。
- **自动发现用全局可改的 `DefaultMySQLSockets`/`DefaultRedisSockets`**（与既有 `ProbeSearchDirs` 同风格的导出变量），使集成测试能清空默认候选而不触碰开发机常驻服务。

## 遗留与风险

- **代码已完成、等待环境验证（ENV-LNX / ENV-BT，Story 1.45）**：真实宝塔机上 vhost 的 `include` 样式（`enable-php-NN.conf`、`rewrite/`、`vhost/ssl/` 片段、`nginx.conf` 的 include 行）与本测试构造的是否一致；宝塔 MySQL 的 `/www/server/mysql/mysql.sock`、Redis socket 的真实属主（受信账号名 `mysql`/`redis`/`www` 的实际取值，若宝塔用 `www` 账号运行 MySQL，则凭据不会发往该 socket，须在 ENV-BT 核对并视情况扩充受信账号表）；真实 Linux 上 `/proc/net/unix` 的列格式（夹具按内核格式构造）；`/www/server/nodejs/v<版本>/bin/node` 的真实布局、nvm/fnm/volta 在真实 Linux 用户下的目录。
- **属后续 Story（不在本次范围）**：1.33 编排接线（调用 `Collect`，把 `NodeInstalls` 的绝对路径用于 website 启动、处理 `dep.nodejs.not_in_path`）；1.42 doctor 与 `status`/`list` 展示 host 信息、`NodeInstalls`、include 的 warning；Server 向导负责收集 MySQL/Redis 的 socket 路径与凭据（本 Story 只提供 `UnixEndpoint`/`MySQLSockets` 入口与只读探测）。
- **已知限制**：glob 不支持 `**`，且字面前缀须在白名单根内（`include /etc/*/x.conf;` 被拒绝并告警）；include 在变量中（`include $x;`）不求值；`Probe` 只展开 `WebServer.Conf` 与 vhost 目录里的文件，不解析 `nginx -T` 的合并输出（那需要执行 nginx，违背只读边界）。
