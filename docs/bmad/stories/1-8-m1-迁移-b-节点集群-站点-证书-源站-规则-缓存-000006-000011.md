## Intent

**Problem:** 1.7 落地了身份/租户/平台核心，但 CDN 控制面的核心实体（节点与集群、站点/域名/源站、证书、统一规则、缓存）仍没有真实表结构；站点子表的租户纵深防御（复合外键）、`rule_versions` 不可变、循环外键的「先建表后 ALTER」只存在于文档与验证骨架里。

**Approach:** 把 database/README §8.1 的 000006–000011 写成真实可发行迁移（28 张表，全部 `expand`、逐表授权），并用真实 MySQL 上的专项测试证明：空库 up、重放幂等、约束/复合外键/唯一键/触发器负向、循环外键、`lingedge_app`/`lingedge_maint` 最小权限负向、租户索引 EXPLAIN，以及对真实迁移文本变异的 DDL 陷阱预检覆盖。

## Boundaries & Constraints

**Always:** 全部 `expand`、可重入；站点子表一律复合外键 `(tenant_id, site_id) → sites(tenant_id, id)`；所有指向 `tenants(id)` 的外键 `RESTRICT`；被 CHECK 引用的外键列不得 `SET NULL`/`ON UPDATE CASCADE`；STORED 生成列的基列外键不得 CASCADE/SET NULL；分区表（`node_heartbeats`）无外键且含 `pmax`；先建无 FK 列、后 ALTER 追加外键；`TEXT/JSON` 无 DEFAULT；SQL 参数化；测试用独立临时 mysqld，用后关闭并删除；未能验证项如实标「等待环境验证」。

**Never:** 触碰本机常驻 MySQL；Docker；Mock 冒充生产；修改 `contract-v1` 已冻结内容；封存（`migrations-seal`）000001–000011（CF-2 才登记）；越界实现 1.9 的表（000012–000013）；push；改 `git config`；改动 `SmartCDN`。

### 范围决策与偏差

- **表数口径**：epics AC1 写 28 张（B 批），累计 A+B = 49；「M1 累计 61 表」是 1.9（000012–000013 再 12 张）完成后的口径，本 Story 只断言 49，并逐表核对 B 批 28 张在 `docs/database/*.md` 均有表节（`TestM1BEveryTableIsDocumentedInDatabaseDocs`）；全表勾选清单属 1.9 AC6。
- **`node_heartbeats` 初始分区**：`p20261120`…`p20261127` + `pmax`（共 9 个；首个分区同时容纳更早时间戳）。分区边界取迁移编写日期；其后写入落入 `pmax`，滚动预建/保留期 DROP PARTITION 由 1.15 的 `partition.maintain` 负责（同 `audit_logs`，已在 1.7 登记依赖）。`lingedge_maint` 对该表授予 `SELECT, ALTER, DROP`。
- **循环外键与 1.9 前置**：`site_rules.current/published_version_id → rule_versions` 在 000010 内用 information_schema + PREPARE 守卫追加（`lingedge:guard`，可重入）；`clusters.confirmed_revision_id`、`sites.last_deployment_id` 此刻为无 FK 普通列，外键由 1.9（000012）追加；`certificates.acme_account_id` 在 P2 建 `acme_accounts` 时追加。
- **大小写不敏感排序规则的影响**：`utf8mb4_0900_ai_ci` 下 `kind IN (...)` 的 CHECK 对大小写不敏感（`NODE_UPGRADE` 能通过），与全库既有约定（status 等）一致；由 Service 层白名单兜底，未为此引入 `BINARY`。
- **`SMALLINT UNSIGNED` 端口**：`origins.port` 的 CHECK 只管下界（`BETWEEN 1 AND 65535`），上界由类型保证（65536 得 ERROR 1264，测试覆盖）。

### 实际验证（本机 macOS arm64、go1.27.4；MySQL 8.0.46 独立临时实例）

- 全部门禁通过（逐项 rc=0）：`make lint`、`make security`、`make gate-selftest`、`make test`、`make race`、`make vuln`、`make contract-check`（`migrations-check`：已发布迁移 0 个）、`make build`、`make verify-build`、`make migrate-test`。
- **空库 up**：`Runner.Up` 在新建空库上执行 000001–000011，0 错误，恰 49 张表（A 21 + B 28，逐名比对），版本 1–11；B 批 28 张均在 `docs/database` 有表节；触发器 4 个（audit_logs 2 + rule_versions 2）；`node_heartbeats` 9 个分区含 `pmax` 且无外键。
- **重放幂等**：第二次 `up` 为空操作；B 批全部语句（含两条 `PREPARE` 守卫的循环外键、触发器重建、GRANT）重放后库结构/授权/触发器/外键数不变；`expand` 拒绝回退。
- **最小权限负向（真实账号）**：app 49 条表级授权（仅 `audit_logs` 为 `Insert,Select`），无库级/全局授权；app 对 B 批表 DROP/TRUNCATE/ALTER/DROP PARTITION/CREATE/DROP TRIGGER/GRANT 全部 ERROR 1142；maint 仅 `audit_logs` 与 `node_heartbeats` 的 `Alter,Drop,Select`，能 `REORGANIZE`/`DROP PARTITION`（旧行随分区消失），对其它表与 DML 全被拒。
- **约束负向（真实库，事务内回滚隔离）**：节点/集群/令牌（哈希格式 CHECK、角色）/节点证书（主体与 node_id 一致 CHECK、级联）/事件（uid 幂等）/心跳（无 FK、pmax、CHECK）；站点（活动名唯一与软删除复用、版本 CHECK）；证书（值域、私钥无默认=1364）；`site_domains`（他租户同域名=1062、软删除后复用、主机名格式 CHECK、默认 `pending`）；11 张站点子表复合外键跨租户=1452；`origins` 跨站点/跨租户绑定源站组=1452、默认源站组每站点唯一；`node_tasks`（8 种 kind、封闭枚举拒绝 exec 类、attempt≤max、有站点必有租户）；`site_rules` type→phase 映射 CHECK；`rule_versions`（UPDATE/DELETE 触发器拒绝，root 与 app 均被拒，`@lingedge_purge=1` 可删；循环外键 SET NULL）；`cache_policies`（默认策略唯一、epoch 仅默认策略、危险开关须确认、`risk_ack_by` RESTRICT=1451）；缓存任务回执（唯一、级联、SET NULL）。
- **租户索引（AC5）**：`information_schema` 断言 15 张 B 批租户表的非主键索引均以 `tenant_id` 打头、或为已登记 `cross-tenant-index`、或为仅含 `uid` 的唯一索引、或为外键支撑索引；8 张租户表 `EXPLAIN FORMAT=TREE` 的租户条件查询走 `tenant_id` 打头索引，漏写条件退化为全表扫描。
- **DDL 陷阱预检覆盖（对真实迁移文本变异）**：CHECK×FK（`cache_policies.risk_ack_by`、`node_certificates.node_id`、`node_tasks.tenant_id` 改 SET NULL；`node_tasks` 复合外键加 ON UPDATE CASCADE）→ 静态 `ddl-check-fk`、真实 ERROR 3823；STORED 生成列×FK CASCADE（`origin_groups`/`cache_policies.default_flag`）→ `ddl-generated-fk`、ERROR 1215；前向外键（证书晚于域名、循环外键内联、`sites` 先于 `site_groups`）→ `ddl-forward-fk`、ERROR 1824；分区表加外键 → ERROR 1506；缺 `pmax` → 越界写入 ERROR 1526。schema lint 变异 10 例均被拦住。
- `pgrep -fl mysqld` 仅剩本机原有 PID 576/744；临时实例与目录已由 `mysqltest` 清理。

| `node_heartbeats` 分区写死 2026-11-20…27，晚于 11-28 迁移则全入 `pmax` | low | 已在偏差中登记，依赖 1.15 `partition.maintain` |
