## 2. 站点创建（分步向导）[M1] → 旅程 2

目标：用最少步骤得到**可发布**的站点；每一步都可保存离开并稍后继续（草稿站点状态「未发布」）。

```
添加网站            ①基本信息 ─ ②域名 ─ ③源站 ─ ④加速范围 ─ ⑤确认并发布
──────────────────────────────────────────────────────────────────────────
① 基本信息
   站点名称*  [ example-site        ]   （仅用于识别，租户内唯一）
   分组       [ 默认分组 ▾ ]
   说明       [                          ]
                                                [取消]  [下一步 ▶]

② 域名                                      
   域名*  [ example.com            ] [＋添加]   ← 失焦即校验：格式 / 是否已被其他站点占用
          ✓ example.com   ✗ www.taken.com  “该域名已被另一个站点占用”（不透露归属租户）
   提示：添加后需将域名 CNAME 至分配的接入地址（站点发布后显示）。

③ 源站
   协议 (●HTTPS ○HTTP)  地址* [ origin.example.com ]  端口 [443]  回源 Host [ 跟随访问域名 ▾ ]
   源站组 [默认源站组]   [＋ 添加备用源站]  权重 [100]  （主/备）
   健康检查 [HTTP ▾] 路径 [/] 间隔 [  ]  ← 默认值由 API 提供
   ⚠ 回源默认校验源站 TLS 证书。[ ] 跳过 TLS 校验（将显示风险提示并被审计）
   ✗ 源站地址不允许指向内网/回环/元数据地址（SSRF 防护）

④ 加速范围
   由平台分配：站点创建后由 LingEdge 按平台的默认放置策略自动接入加速节点，**租户无需也无法选择集群/节点**，不展示节点名、节点数或在线数。
   （仅 Admin 代租户时，此步骤下方另有「平台区块 · 放置集群」：平台人员可选择/调整该站点的服务集群，对应平台独占接口 `PUT /sites/{siteId}/cluster-bindings`；Console 不渲染该区块。）

⑤ 确认并发布
   摘要：站点名 / 域名 2 / 源站 1 / 缓存：默认策略 / 真实 IP：默认(X-Forwarded-For、X-Real-IP 开启)
   校验：✓ 全部通过        证书：⚠ 尚未绑定证书（仅 HTTP 可访问）[去上传证书]
   [上一步]  [仅保存，稍后发布]  [发布 ▶]
```
- 「仅保存」→ 站点状态「已保存，未发布」。「发布」→ 打开发布抽屉（§6）。
- **失败路径**：源站 SSRF 校验失败、域名冲突、站点尚未被平台分配加速范围（`409 site.no_cluster_bound`，提示「加速范围尚未配置，请联系平台管理员」）→ 在对应步骤内就地报错，下一步被阻止；不允许带错进入确认页。
- 默认值（缓存策略、XFF 等）由后端给出，UI 不硬编码；摘要中的默认值标「默认」。
- 平台尚无可用集群时（Admin 视角）：显示空态「还没有集群，请先在节点管理中创建集群并注册节点」，跳转链接（有权限时）；Console 视角仅提示「加速服务暂未就绪」。

```
源站组：默认源站组 ▾  [＋ 新建源站组]
```

## 4. 网络设置 → 真实 IP 传递 [M1] → 旅程 3（闭环 E，最关键页面）

### 4.1 页面标签与方向区分
网络设置下三个标签：**真实 IP 传递（出站）** · **入站可信代理** · 回源与端口。

```
网络设置                [ 真实 IP 传递 ]   入站可信代理     回源与端口
┌ 方向示意 ──────────────────────────────────────────────────────────────────────┐
│  访客 ┄┄┄┄▶ LingEdge 节点 ━━━━━━━━━━▶ 您的源站                                  │
│  1.2.3.4     识别客户端 IP     本页配置：LingEdge 向源站发送哪些 Header          │
│  （虚线：访客→LingEdge，不在本页配置；实线：LingEdge→源站，在本页配置）            │
└────────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 配置区
```
┌ 向源站传递的 Header ─────────────────────────────────────────────────────────┐
│ ☑ X-Real-IP          始终以 LingEdge 验证后的客户端 IP 覆盖访客发来的同名值    │
│ ☑ X-Forwarded-For    传递策略  (●) 覆盖为真实 IP   ( ) 在可信链路上追加         │
│                      ⓘ 追加：仅在请求来自「可信代理」时保留其上游 XFF 链          │
│ ☑ 自定义 Header      名称* [ Ling-Client-IP        ]   ✓ 名称合法              │
│                      ⓘ 同名的访客请求 Header 会被覆盖，不能伪造                  │
│                      ✗ 示例错误：“Authorization 是保留 Header，不可使用”         │
│                      ✗ 示例错误：“名称只能包含字母、数字和 - _，且不能含冒号/换行” │
│ ⚠（三项都关闭时）源站将无法获得真实客户端 IP。                                  │
│                                                         [重置]  [保存]          │
└────────────────────────────────────────────────────────────────────────────────┘
```
**校验与提示（逐条）**
| 场景 | 呈现 | 阻止保存 |
|---|---|---|
| 名称含非法字符/空格/冒号/换行 | 字段下红色错误：原因 + 允许字符说明 | 是 |
| 名称超过长度上限 | 「最多 N 个字符」，N 来自 API 约束 `[ARCH]` | 是 |
| 名称命中保留 Header（Host、Content-Length、Transfer-Encoding、Connection、Upgrade、Cookie、Set-Cookie、Authorization 等；完整清单由架构给出） | 「X 是保留 Header，不能使用」+「推荐命名：`Ling-Client-IP`」 | 是 |
| 名称与已开启的 `X-Real-IP`/`X-Forwarded-For` 重复 | 「与上方标准 Header 重复」 | 是 |
| 名称大小写与规范不同（如 `ling-client-ip`） | 非阻止提示：「HTTP Header 名不区分大小写，建议 `Ling-Client-IP`」，**不自动改写** | 否 |
| 三项全部关闭 | 警告条，不阻止 | 否（用户可能有意如此） |
| **修改已发布的名称** | 保存时弹出 L2：「源站若使用旧名称读取真实 IP，发布后将读不到。建议先让源站同时兼容新旧名称，再发布，最后回收旧名。」 | 否 |

```
│ 当前已生效版本 v127（自定义 Header：X-Client-IP）                  [查看差异][发布]│
│                                                                                │

```

```
│                                                                                │
```

```
│  识别到的客户端 IP     198.51.100.7   依据：TCP 对端地址（未处于可信代理链路）     │
│  访客伪造值            Ling-Client-IP: 6.6.6.6 → 已被覆盖                        │

└────────────────────────────────────────────────────────────────────────────────┘
```
- 调试是受控的白名单任务（`realip.debug`，非任意命令）：节点在引擎内以**与真实请求相同的纯函数**做模拟（模拟对端地址只是函数入参），**不会向源站或本机发起真实请求**；结果只返回**该次模拟**的识别与 Header，不暴露节点内部信息，租户也可用（NFR-14）。
- 节点尚未生效当前版本时，结果顶部标注「模拟所用配置为 v127，尚未应用本次更改」（不显示节点名）。
- 失败：节点离线/超时 → 明确原因 + 重试；不返回虚构结果。

- **一次性机密不可找回（刻意设计，Story 1.37b 复核确认）**：TOTP 密钥/otpauth 链接、恢复码、自动生成的迁移口令只在对应响应里出现一次，服务端不保存明文，向导也不把它们放进任何浏览器存储。因此在「已显示、尚未保存/确认」时刷新或关闭页面，这些值**无法在向导内重新取得**：TOTP 与恢复码——管理员账号已创建但 TOTP 未启用，登录 Admin 后在账号安全里重新绑定（不影响安装）；迁移口令——在 root 侧用 `lingedge-server migrate credential reset --admin-user <管理员>` 重置。界面在显示这些值的位置有「仅此一次」强提示，并要求勾选「我已保存」后才能继续；不为「找回」增加任何把机密落盘或回传的通道。
- **失败与恢复**：每步可返回；中途关闭浏览器后再次进入，从已完成的最后一步继续（状态持久化）；数据库步骤失败显示具体原因与可重试。
- **完成后**：`install.lock` 存在 → 向导路径（`/setup` 与 `/api/v1/public/setup/*`）统一返回 `410 setup.already_installed`（MIN-04，2026-11-16 修订；不是 404/403）；令牌立即作废。
- **实现说明（Story 1.37）**：已按本节落地 8 步、令牌门禁、口令强度与二次确认、TOTP 二维码与恢复码（需勾选「我已保存」）、完成页 Admin 地址与 `master.key` 强提示。与线框的差异：①线框中的「下载恢复材料」按钮未做——`master.key` 的唯一生成者是 Tools（步骤 18，tools-design §13），向导不持有其内容，只强提示「须与数据库备份分开保管」并要求勾选确认；②「用户名」字段未做——管理员以邮箱登录（OpenAPI `SetupAdminCreate` 只有 email/display_name）；③主题跟随系统 `prefers-color-scheme`（Story 1.37b 起；顶栏可显式选「浅色/深色」，同一标签页内保留），服务端回执/检查项/错误说明按稳定标识映射为界面语言（未知内容回落服务端原文并标注其语言）；④MySQL 步骤新增「Unix socket」连接方式（CC-13）。

**发布流程与状态**
| 状态 | 含义 | 前台 |
|---|---|---|
| 草稿 | 编辑中，自动保存 | 不可见 |
| 已修改，未发布（CMS） | 草稿与线上版本有差异（CMS 专用词，**不用**配置域的「已保存，未发布」，避免撞词） | 不可见；仅受保护预览链接可见 |
| 已排期（今日/某日 09:00） | 对应 CMS `scheduled`；与配置域的「已保存，未发布」不同；引用校验失败时显示「排期失败」 | 到点自动发布；可取消/改期 |
| 已发布 | 线上版本 vN | 可见（SSR 立即；SSG 降级为「重新生成后」并显示生成进度） |
| 已回滚至 vN | 回滚产生新版本记录 | 恢复 |

- **预览**：生成**有时效的受保护链接**（不透明令牌、可单独撤销；令牌置 URL fragment，不进 access log；不可被搜索引擎收录，`noindex`，过期失效）；预览内容与发布后渲染一致。
- **定时发布**：时区明确（显示用户时区与 UTC）；到点前再次校验（引用的媒体/套餐存在）；校验失败则**不发布并通知**，不静默失败。
- **版本历史抽屉**：版本号、时间、作者、备注、状态；选两个版本对比（模块级 diff + 预览并排）；「回滚到此版本」= 创建一个内容与该版本一致的新版本并发布（L2 确认）；不删除历史。
- **多语言**：语言切换 Tab 显示每种语言的完整度；缺失字段标红点；发布时若某语言不完整，给出「回退策略」说明与确认。
- **模块排序**：拖拽 + 键盘替代；模块可隐藏（👁）。
- **套餐价格模块**：显示 🔒「价格来自产品计费，此处不可编辑」+ 链接；**不提供价格输入框**（FR-45、R-12）。自用模式下该模块不可用。
- **节点地图/可用率等数据模块**：编辑者只选择**数据来源**（实时/示意），**不能手输数值**；选「示意」时前台强制渲染「示意」角标；选「实时」但无可用数据源时，前台自动隐藏该模块或显示「暂无数据」（由模块配置决定），不显示数字。见 `website.md` §3。
- **并发**：同一页面同时被他人编辑 → 版本号冲突对话框（EXPERIENCE.md · 表单校验）。
- **审计**：保存草稿不审计每次自动保存，**发布/回滚/定时/取消定时**一律审计。
- 手机上：只读 + 文本类轻量编辑，提示「复杂排版建议在桌面端进行」。
