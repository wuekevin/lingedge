# LingEdge（凌界云）· EXPERIENCE.md

> 本文件拥有「怎么工作」。页面线框见 `screens.md`；IA 全表见 `ia.md`；CLI/TUI 见 `cli-tui.md`；官网见 `website.md`。视觉令牌以 `{colors.*}` 等语法引用 `DESIGN.md`。**与线框/Mock 冲突时本文件胜出。**
> 标记：`[ASSUMPTION]` = UX 提议、基线与 PRD 未规定，可被用户推翻；`[ARCH]` = 需要架构/API 配合的 UX 需求。

## Foundation

**表面（形态）**：三个 Web 表面 + 一个终端表面。

| 表面 | 技术 | 形态 | 主要人物 |
|---|---|---|---|
| Admin | Vue 3 + TS + Vite + **Arco Design Pro** + Pinia + Vue Router + Vue I18n + ECharts | 桌面优先的响应式后台 | 平台运营者陈工 |
| Console（P5） | 同上；与 Admin 同组件库、**独立入口与构建** | 桌面优先的响应式后台 | 站点所有者林敏 |
| 官网 | **Nuxt 3** + Tailwind；M1 为 SSG 静态，P2 CMS 起 SSR（D-8） | 移动优先的内容站 | 访客王先生、编辑周编辑 |
| Tools（`lingedge`） | Go + Cobra + Bubble Tea | 终端 TUI + 非交互 CLI | 陈工 |

**UI 系统继承**：Admin/Console 继承 Arco Design 的组件结构与交互默认值，EXPERIENCE 只规定**行为差量**；视觉差量（主题令牌）见 `DESIGN.md` · Arco 定制边界。官网为自有组件 + Tailwind，行为遵守本文件同名规范。

**两条产品级约束**（贯穿所有表面）：
1. **真实性**：任何界面不得用假数据/假状态冒充生产（NFR-1）。无数据 → 空态；未交付 → 不渲染；示意 → 明确标注。
2. **「保存」≠「生效」**：对会影响节点行为的配置，界面必须始终分清「已保存」「已发布」「已在 N/M 节点生效」三个事实（见 §配置状态表达）。

## Information Architecture

完整菜单/页面/阶段表在 `ia.md`，此处只固定**规则**：

- **Admin 17 个一级菜单**（基线 §6.1 顺序）；**M1 只渲染其中 9 个**，其余随模块交付出现，不放灰色占位（FR-31、NFR-1）。
- 菜单可见性 = 模块已交付 ∧ 有权限 ∧ 运行模式允许。
- 一个能力一个规范页面；其他入口是别名/范围视图。
- 站点是 Admin/Console 的一等对象：站点详情有自己的二级导航（站点概览…部署记录），与 Console 共用组件。
- 网络设置下**必须在视觉与文案上区分两个方向**：出站「真实 IP 传递（LingEdge → 源站）」与入站「可信代理（访客侧前置代理 → LingEdge）」，避免把基线 §9.1 的方向搞反。
- 全局：顶栏（品牌、全局搜索、语言、主题、告警/通知、用户菜单）、侧栏（一级菜单，可折叠）、多标签栏、内容区。
- 官网导航：见 `ia.md` §3 与 `website.md`。

**表面闭合检查**（每个已述需求都有页面落点、每个页面都有旅程到达）：基线 §7 用户必须能做的 12 件事 → Console 站点详情各页；闭环 A–J → `screens.md` 与 `cli-tui.md` 的旅程；官网注册→进入控制台 → `website.md` 的入口规则。

## Voice and Tone

微文案。品牌气质见 `DESIGN.md` · Brand & Style。**原则：精确、可操作、不夸大、不拟人。**

| 要 | 不要 |
|---|---|
| 「已保存为草稿，**尚未发布到节点**。」 | 「保存成功！」（会让人以为已生效） |
| 「已发布到 12/14 个节点，2 个节点离线，将在恢复后补发。」 | 「发布成功」（离线节点未生效时） |
| 「Header 名称不能包含冒号或换行。」 | 「输入有误」 |
| 「该操作会移除所有节点上的此站点服务，且不可撤销。请输入站点名称 `example-site` 确认。」 | 「确定要删除吗？」 |
| 「暂无流量数据。站点接入后 1–5 分钟内出现首批数据。」`[ASSUMPTION: 时间窗口由监控聚合周期决定]` | 「流量 0（示例数据）」 |
| 「该功能将在 P3 提供」→ **不显示**；只在 Docs/更新日志里说 | 在菜单里放「敬请期待」 |
| 「全球 12 个节点（实时，更新于 14:03）」 | 「全球 200+ 节点」（无数据源） |
| 「CDN WAF/CC **不等同于**独立的大规模 L3/L4 DDoS 清洗。」 | 「无惧任何攻击」「军工级防护」 |

- 术语必须逐字使用 PRD §3 术语表（站点、域名、源站、源站组、集群、节点、配置版本、部署、规则、执行阶段、真实 IP 传递…），不引入同义词（例如不称「网站」「站点」混用——后台菜单沿用基线「网站管理」，页面内对象统一称「站点」）。
- 错误文案结构固定为：**发生了什么 → 为什么（若已知） → 怎么办**；附 **Request ID**（可复制）。禁止只显示错误码。
- 语气：陈述句、中性、第二人称「您」（官网）/省略主语（后台）。不使用感叹号、不使用表情符号。
- 中英文：所有文案进 i18n 键，键命名与规范见 §i18n。

## Component Patterns

行为规则（视觉规格在 DESIGN.md · Components）。

| 组件 | 用在 | 行为规则 |
|---|---|---|
| **统一数据表格** `LeTable` | 所有列表 | 服务端分页/排序/筛选（API 分页，基线 §19）；筛选条件写入 URL 以便分享与返回；多选 + 批量操作栏吸顶；列可配置显示；空/加载/失败三态内置；操作列固定右侧；行点击进入详情，行内操作用「⋯」菜单；危险操作不放在一眼可点的位置 |
| **状态胶囊** `LeStatus` | 一切状态 | 图标 + 文字 + 语义色；文案来自固定词表（§配置状态表达）；Hover 给出原因与时间 |
| **发布条** `LePublishBar` | 站点详情所有子页 | 有「已保存未发布」更改时吸顶显示琥珀条：「有 N 项未发布更改 · [查看差异] [发布]」；无更改时收为一行中性「已发布 · 版本 v128 · 12/12 节点生效」。**点击「发布」永远先打开发布抽屉，不直接发布** |
| **配置差异** `LeDiff` | 发布抽屉、配置版本、CMS 版本 | 以人类可读的「变更项」分组（新增/修改/删除），可切换「原始配置 diff」；真实 IP 与规则变更用语义化描述（例：「真实 IP 自定义 Header：`X-Client-IP` → `Ling-Client-IP`」）|
| **危险确认** `LeConfirm` | 见 §危险操作 | 四级强度；说明影响范围；页脚固定审计提示 |
| **权限按钮** `LeAuthButton` | 全局 | 无权限：禁用 + Tooltip 写明缺少的权限点；不对「整页不可见」的权限使用 |
| **代码块** `LeCode` | Nginx 片段、CLI 命令、Header 示例、Request ID | 一键复制，复制后短暂提示；占位值高亮且复制保持占位符原样；长片段可折叠 |
| **异步任务进度** `LeTask` | 发布、刷新、升级、备份 | 显示 Task ID、阶段、逐目标（节点）结果；可离开页面，任务在「任务中心」可回溯；`aria-live="polite"` 播报阶段变化 |
| **规则条件构建器** `LeCondBuilder` | 规则编辑器 | 嵌套 AND/OR/NOT 分组；字段 → 适用操作符联动（不适用的灰掉）；值输入按类型（CIDR、正则、枚举）校验；**M1 未启用的字段（ASN/国家/地区）显示为禁用项并写明原因**，不隐藏也不假装可用（D-15） |
| **指标卡 / 图表** | 工作台、统计 | 标题 + 单位 + 时间范围 + 更新时间；无数据空态；可切换「数据表」视图；刷新不闪烁（保留旧数据 + 顶部细进度） |
| **节点出口 IP 清单** | 真实 IP 页、站点概览 | 来自当前绑定集群的真实出口 IP；为空时给出明确提示而非占位 IP |
| **租户/代管横幅** | Admin 顶栏下 | 固定、不可关闭；写操作带「代管」审计标记 |
| **全局搜索** | 顶栏 / ⌘K | 站点、域名、节点、页面（菜单）、命令；受权限与租户边界约束；`↑↓` 选择、`Enter` 打开、`Esc` 关闭；不搜日志正文 |
| **多标签页** | Admin | 同一页面（同参数）不重复开标签；关闭有未保存更改的标签先确认；最多 12 个标签，超出时关闭最久未用的**无更改**标签 `[ASSUMPTION]`；刷新页面恢复标签但不恢复未保存表单 |

## State Patterns

### 全局三态 + 变体

每个页面/数据区块**必须**实现下表全部状态（FR-30 可验证项），缺一不可发布。

| 状态 | 视觉与行为 | 文案规则 |
|---|---|---|
| **加载中（首次）** | 骨架屏，结构与最终布局一致；>10s 追加「仍在加载…」与取消/重试 | 不用无限转圈单独表达 |
| **加载中（刷新）** | 保留旧数据，顶部细进度条；不清空内容 | — |
| **失败** | 区块级错误卡（不是整页白屏）：原因 + 重试 + Request ID（可复制）；网络断开与服务端错误、无权限（403）、不存在（404）、冲突（409，资源冲突）、并发修改（**412** `resource.precondition_failed`，提示「已被他人修改，请刷新」）、校验（400）、限流（429）分别给出不同文案 | 「无法加载站点列表：主控暂时不可用。[重试] Request ID: `r_8f3a…`」 |
| **空数据** | 说明「为什么为空」+ 下一步（一个主操作）；**数据类空态绝不显示示例数字** | 区分「尚无数据」（新站点）与「筛选无结果」（提供清除筛选） |
| **部分失败** | 如 12/14 节点成功：列出失败项、原因、可重试范围 | 不得只显示总体「成功」 |
| **过期数据** | 数据超过期望新鲜度（如节点心跳超时）时显示「数据已过期，最后更新 hh:mm:ss」 | 不把过期当作当前值 |
| **主控不可达（对终端用户）** | Admin 整体横幅「无法连接主控」，只读缓存视图显式标注「缓存数据」；写操作禁用 | **节点数据面不受影响**（基线 §3.1）——横幅需声明「已发布配置的节点仍在正常服务」 |
| **只读/无权限** | 见 ia.md §4 第 5 条 | — |
| **功能未交付** | **不渲染**（菜单、页面、Tab、字段） | — |

### 配置状态表达（「已保存但未发布」与「已发布到 N/M 节点」）

这是 LingEdge 最核心的状态语言：对任何**会进入节点配置**的对象（站点设置、域名、源站、缓存、规则、真实 IP 传递、证书绑定、TLS、入站可信代理…），界面只能使用下面这套**固定状态词**。

**事实模型**（与 FR-55/56 对齐）：站点编辑 → **已保存**（写入主控，仍是「草稿态更改」）→ 发布 → 主控生成**不可变、已签名的配置版本** → **部署**到一组目标节点 → 每个节点单独汇报**实际生效版本** → 汇总为 N/M。

| 状态词（固定） | 图标 | 色 | 含义 | 出现位置 |
|---|---|---|---|---|
| **已保存，未发布** | 圆点+笔 | 警告（琥珀） | 主控中的设置与最新已发布配置版本**不同**；节点**尚未**应用 | 发布条、每个有未发布更改的对象行（小圆点）、站点列表 |
| **校验失败** | 叉 | 危险 | 保存的内容无法通过发布前校验（FR-68）；**阻止发布** | 发布抽屉顶部、对象行 |
| **排队中** | 时钟 | 中性 | 同一集群已有发布在进行，本次发布在队列中等待（集群内发布串行，ADR-002）；对应 API `queued` | 发布条、部署记录 |
| **发布中 · 已生效 N/M** | 旋转 | 信息 | 部署进行中，N 个目标节点已汇报生效 | 发布条、部署记录 |
| **已暂停**（**仅 Admin 可见**） | 暂停 | 警告 | 平台暂停了灰度批次，等待平台人员继续/取消；**Console 不展示该词**，租户侧仍显示「发布中」 | Admin 部署记录 |
| **已发布 · N/M 节点生效**（N<M） | 半圆 | 警告 | 部署已结束，仍有节点**未生效**（失败/离线/维护）。后附原因计数：「1 失败 · 1 离线」 | 发布条、站点概览、部署记录 |
| **已全部生效 · M/M** | 对勾 | 成功 | 所有目标节点汇报的实际生效版本 = 目标版本 | 同上 |
| **发布失败** | 叉 | 危险 | 无节点应用新版本，**节点保持上一有效版本继续服务**（FR-56） | 部署记录、发布条 |
| **已回滚至 v126** | 回环 | 信息→成功 | 回滚部署已完成；显示回滚前后的版本 | 部署记录 |
| **草稿**（仅 CMS） | 笔 | 中性 | 内容草稿，前台不可见 | CMS |
| **已排期**（仅 CMS） | 时钟 | 信息 | 已设定定时发布时间，到点由系统发布；对应 CMS `scheduled` | CMS |

**铁律**
1. **永远不在 N 未达 M 时说「已生效」或「发布成功」**。toast 文案按事实选择：
   - 保存后：「已保存为草稿，**尚未发布到节点**。[去发布]」
   - 发布完成且全部生效：「已全部生效：14/14 节点正在使用版本 v128。」
   - 发布完成但有未生效：「已发布到 12/14 个节点（1 个失败、1 个离线）。未生效的节点仍在使用 v127，离线节点恢复后将自动补发。[查看详情]」
2. **N 与 M 的定义**必须可解释：M = 本次部署的**目标节点**（已绑定集群中、非维护、站点所属）；N = 汇报「实际生效版本 = 目标版本」的节点数；不是「已推送」数。Hover 显示定义。`[ARCH]` 需要「节点实际生效版本」汇报通道（FR-56 已要求）。
3. **离线/维护节点**单独计数并解释，不静默计入失败，也不静默剔除 M。
4. **灰度（仅 Admin/平台视图）**：Admin 发布抽屉选择范围（单节点/一批/全部）；灰度中状态显示「灰度 · 3/14 节点生效，其余保持 v127」，并提供「继续扩大范围」与「回滚」两个主操作。
4a. **（修订）灰度策略由平台设定，租户不选择、也看不到**：Console 发布抽屉**没有**范围/灰度选项（只有变更摘要、校验结果、确认），灰度、批次、失败暂停均由平台在集群设置里定义（BLK-02）；上面第 4 条的「单节点/一批/全部」范围选择与「继续扩大范围」「回滚」主操作**仅出现在 Admin（平台）视图**，Console 只显示计数进度与摘要。
5. **规则/真实 IP 等对象级回滚**有两条路，必须区分：**站点级回滚** = 把所选历史**配置版本**作为一次新的部署重新发布（版本不可变，不改写历史）；**规则级「恢复到此版本」** = 把规则内容改回旧版本并保存为「已保存，未发布」更改，仍需发布。界面上两个入口措辞不同、不得混淆。
6. **Console 粒度**：租户只看到计数与进度（N/M、失败原因的摘要），看不到节点名/IP；Admin 看逐节点明细。
7. 状态词与上表**一一固定**，页面不得自造同义词（如「已同步」「已下发」「已提交」）。
8. **API 枚举 → 固定状态词的唯一映射表**在 `docs/api/README.md` §7（`PublishState`：`never_published/published/unpublished_changes`；租户部署状态 `queued/running/success/failed/canceled/rolled_back`；平台部署状态 `pending/running/paused/success/partial_failed/failed/canceled/rolled_back`）。UI 只依据该表取词，不自行推断。`paused` 对租户折叠为「发布中」，`partial_failed/failed` 折叠为「发布失败」（有部分节点生效时为「已发布 · N/M 节点生效」）。
9. **版本号口径**：租户界面中的 v126/v127/v128 是**站点线性版本 `site_version`**（站点内单调，API `version_no`）；集群修订序号 `seq` 是平台内部概念，仅 Admin 可见，Console 不展示（否则会看到跳号并侧漏他人发布频率）。

**发布前校验呈现**：发布抽屉分三段——① 变更摘要（LeDiff）② 校验结果（通过/失败项逐条，失败项可点击跳转到字段）③ 发布范围与确认。校验失败时「发布」按钮禁用并说明；不允许「忽略错误继续」。

### 表单校验

- **实时 + 提交双重**：字段失焦时校验格式；提交时校验整表并聚焦第一个错误；服务端校验失败统一为 **400 `validation.failed` / `config.validation_failed`**（`details[]` 逐字段，ADR-017；不使用 422，仅幂等键误用为 422 `idempotency.key_reuse`，属协议误用，不映射到字段），按 `details[].field` 映射回字段。
- 校验信息写在字段下方，文字 + 图标，`aria-describedby` 关联；错误汇总在表单顶部（长表单）。
- **约束来源**：长度上限、保留名单等由 API 的约束元数据提供（`[ARCH]` 「约束随接口返回」），UI 不硬编码，避免与服务端漂移。
- 破坏输入时不静默改写（例如不自动把大写 Header 名改成小写；而是提示规范写法）。
- 敏感字段（密码、私钥、Token、凭据）：输入遮盖、可切换显示、**不回显保存值**（写后只显示「已设置」+ 指纹/末四位）、不进浏览器自动填充（`autocomplete="off"`/`new-password`）、不进前端日志。
- 离开未保存页面前确认（标签页关闭、路由切换、刷新）。
- 乐观并发：编辑对象携带版本号；保存时若对象已被他人修改，弹出**冲突对话框**：显示「他人更改」与「我的更改」，选择「采用他人版本 / 用我的覆盖 / 逐项合并」。`[ARCH]` 需要 ETag/版本号。

### 危险操作与审计提示

按**影响面与可逆性**分四级，强度递增：

| 级别 | 例 | 交互 |
|---|---|---|
| **L1 可撤销** | 停用规则、移动站点到分组 | 立即执行 + toast「已停用。[撤销]」（8 秒） |
| **L2 确认** | 节点进入维护、停用站点、发布、回滚到上一版本、吊销 API Token | 对话框：说明**影响范围**（「将影响 3 个域名，约 N 个节点」）与后果；确认键用动词（「发布到 14 个节点」），不用「确定」 |
| **L3 输入确认** | 删除站点/域名/证书、解除集群绑定、吊销节点证书、整站缓存失效、关闭强制 HTTPS | 在 L2 基础上要求**输入对象名称**；确认键为危险色并初始禁用 |
| **L4 重新验证身份** | 修改运行模式、创建/提权管理员（`setUserRoles`、创建平台用户）、修改角色与权限、重置管理员密码、吊销节点证书、SSRF 白名单与签名密钥轮换、卸载类（清单以 OpenAPI 的 `x-reauth: true` 为准） | 在 L3 基础上要求**重新输入密码（已启用 TOTP 则另输 TOTP）**：前端调用 `POST /auth/reauth`，成功后会话进入**再认证窗口**（系统设置 `auth.reauth_window_s`，默认 300 秒 `[ASSUMPTION]`），窗口内不重复询问；窗口外直接调用被拒绝 `403 auth.reauth_required`，前端据此弹出验证框并自动重试原请求 |

- 所有 L2 及以上对话框**页脚固定显示审计提示**：「此操作将记录到审计日志（操作人、时间、对象、Request ID）。」代管操作追加「代管租户：xxx」。
- 操作完成后，toast/结果面板提供「查看审计记录」链接（带 Request ID 过滤）。
- **不可逆迁移/不可简单回退**的升级确认见 `cli-tui.md`；Admin 内凡显示升级信息处，不得出现「一键回退」的措辞，只呈现「恢复备份」路径。
- **缓存规则中放宽默认隔离**（缓存带 `Set-Cookie` 响应、缓存带 `Authorization` 请求；FR-69）：属于 L3，红色风险提示「可能导致一个用户的动态内容被其他用户看到」，要求输入「我了解缓存泄漏风险」类确认语 `[ASSUMPTION: 具体确认语文案可调]`，并被审计。
- **批量危险操作**：确认对话框列出受影响对象清单（可滚动），确认语为数量（「删除 5 个站点」）。

### 其他全局状态

- **会话过期**：保存草稿到本地（仅非敏感字段）→ 弹出重新登录 → 成功后返回原页面，表单内容恢复。
- **权限变化**：接口返回 403 时，页面不崩溃：显示权限不足卡片并建议刷新权限。
- **只读运行（升级维护中）**：横幅「系统维护中，暂时只读」，写操作禁用；不显示虚构倒计时。

## Interaction Primitives

- **键盘**：全站可纯键盘操作。`⌘K`/`Ctrl+K` 全局搜索；`g` 后接 `d/s/n` 跳转 工作台/站点/节点 `[ASSUMPTION]`；`?` 显示快捷键；表格 `↑↓` 移动、`Space` 选中、`Enter` 打开。所有快捷键可在个人设置关闭。
- **拖拽**：规则优先级排序、CMS 模块排序均支持拖拽，**同时提供键盘与按钮替代**（上移/下移/移到第 N 位），并通过 `aria-live` 播报新位置。
- **复制**：Header 名、IP、版本号、Request ID、命令、Nginx 片段均有复制按钮；复制成功给出 toast 与按钮文本变化（「已复制」）。
- **时间**：绝对时间显示为用户时区，hover 显示 UTC 与相对时间；时间范围选择器提供「近 1 小时/24 小时/7 天/自定义」，范围写入 URL；时间窗口超出数据保留期时提示而非返回空（保留期默认值待用户确认，OQ-7）。
- **数字单位**：带宽用 bps 十进制（Kbps/Mbps/Gbps）；流量用 1024 进制并标注 GB/MB `[ASSUMPTION: 计费口径在 P5 定义后可覆盖，导出表头标注进制]`；数字等宽、千分位随语言。
- **长任务**：任何耗时 >2s 的操作返回 Task ID（基线 §19），UI 立即给出任务进度抽屉，用户可关闭抽屉、任务继续；完成时若用户仍在站内，非阻塞通知。
- **自动刷新**：监控页默认 30s 自动刷新 `[ASSUMPTION]`，可暂停；编辑类页面**不**自动刷新以免覆盖用户输入，改为检测到远端变化时提示「内容已更新 [刷新]」。
- **动效**：过渡 ≤200ms；尊重 `prefers-reduced-motion`（降为瞬时切换，进度条改为静态百分比）。

## Accessibility Floor

目标：**WCAG 2.1 AA**（官网与后台）。视觉对比度见 DESIGN.md（所有正文/语义色组合已按 ≥4.5:1 选值，`text-disabled` 为已声明例外）。行为底线：

- **键盘可达**：所有交互元素可聚焦、焦点顺序符合视觉顺序、焦点环清晰（≥2px，对比度 ≥3:1）；模态/抽屉焦点陷阱 + `Esc` 关闭 + 关闭后焦点回到触发元素；提供「跳到主内容」链接。
- **不靠颜色**：状态 = 图标 + 文本 + 颜色；图表系列用形状/线型/直接标签区分，并提供「数据表」替代视图。
- **语义与标签**：表单控件有可见标签；图标按钮有 `aria-label`；表格用 `<th scope>`；状态变化用 `aria-live`（发布进度 `polite`，发布失败 `assertive`）。
- **目标尺寸**：触控目标 ≥44×44px（官网/移动）；后台桌面控件 32px 高但有 ≥24px 命中区（AA 2.5.8）。
- **缩放与重排**：200% 缩放与 320px 宽无横向滚动（表格内部横向滚动除外，且有滚动提示）。
- **时间限制**：会话过期前 2 分钟提示并可续期；自动刷新可暂停。
- **语言**：`<html lang>` 随界面语言切换；中英混排片段标注 `lang`。
- **CLI/TUI**：见 `cli-tui.md` · 可访问性（`--plain`、无色、行式输出，可被读屏器读取）。
- **验证**：每个页面完成时走一遍键盘专项 + 读屏冒烟；自动化 axe 检查纳入前端组件测试（基线 §23「前端组件测试」）。`[ASSUMPTION: 具体门槛由测试计划定]`

## i18n 规范

- **语言**：`zh-CN`（默认）、`en`。Admin/Console/官网/Tools 全部覆盖（NFR-29）；缺失翻译键由 CI 阻断；运行时缺失回退到 `zh-CN` 并在开发环境告警。
- **键命名**：`{surface}.{module}.{page}.{element}`，如 `admin.site.network.realIp.customHeader.label`；**禁止**用中文文本当键；**禁止**拼接句子（用带命名占位符的完整句 `{count}`、`{name}`）；复数/数量用 ICU 风格消息格式（中文无复数、英文需处理）。
- **文案长度**：英文平均比中文长 30–50%，布局不得依赖字符数；按钮、标签、Tab 允许换行或省略+Tooltip；表头不定宽截断关键信息。
- **不翻译的内容**：产品名 LingEdge、术语缩写（CDN/WAF/DNS/TLS/CIDR/ASN）、HTTP Header 名、命令、配置键、枚举值（原样展示，旁注本地化说明）、用户自己的内容。
- **品牌**：中文「LingEdge（凌界云）/ 凌界云」，英文「LingEdge」。
- **格式**：日期时间、数字、货币、单位用 `Intl` 按语言环境格式化；金额定点小数 + 币种代码（基线 §16 不用浮点，前端只格式化后端给的字符串/整数分，不做浮点运算）。
- **错误码文案**：后端返回稳定错误码（`[ARCH]`），前端按语言映射为文案；未知错误码回退到「发生未知错误」+ Request ID。
- **CMS 内容的多语言**：每个内容单元独立维护 zh/en 版本与「翻译完整度」指示；缺失某语言时，官网该语言页面**回退策略**可配置（回退默认语言并显示提示 / 隐藏该内容）`[ASSUMPTION]`。
- **CLI**：随 `LANG`/`LC_ALL` 选 zh/en，可用 `--lang` 覆盖；机器可读输出（`--json`）**字段名与枚举值不本地化**。

## Inspiration & Anti-patterns

参考对象仅限**公开功能与设计理念**（基线 §1.1）：Cloudflare 的「规则 = 条件 + 动作 + 阶段」与站点级分层导航、EdgeOne 的站点配置分区、CDN1 的节点集中管理、Certimate 的证书 Provider 思路。**不复制**其界面、文案与资源。

**反模式（明确不做）**
- 「保存成功」即暗示「已生效」；
- 把节点数/可用率写成无来源的营销数字；
- 菜单里放不可用的灰色功能或「敬请期待」；
- 网页里提供任意 Shell/终端入口；
- 用 Mock 数据让页面「看起来完整」；
- 在后台滥用渐变与发光；
- 默认密码、默认管理员提示；
- 把「出站传递 Header」与「入站可信代理」放在同一个开关里。

## Key Flows

> 以**命名人物**叙述，逐步骤有「climax beat」（关键时刻）。每个旅程的页面线框与逐屏细节见 `screens.md` / `cli-tui.md`。人物为叙述示意人物，沿用 PRD §2.3。

### 旅程 1 · 陈工从终端装好主控并完成 Web 初始化（闭环 A）→ `cli-tui.md` §3、`screens.md` §9
1. 陈工在干净服务器上运行 `lingedge`，TUI 列出菜单，选「1 安装组件」，勾选 Server + Admin Web + Website。
2. 预检阶段发现 53 端口之类冲突或宝塔已装 Nginx → 停在冲突步骤，给出选项（改端口/取消/按指示处理），**不自动改动**。
3. 安装完成，终端输出「Web 初始化地址 + 一次性初始化令牌」。
4. 浏览器打开地址，输入令牌进入向导：环境检查 → MySQL → Redis → 初始化数据库 → **创建管理员（自设密码，无默认密码）** → 基础配置 → 密钥初始化 → 完成。
5. **Climax**：向导最后一步显示「安装已完成，初始化向导已关闭」，`install.lock` 生效；刷新向导地址得到 404，只能进入 Admin 登录页。

### 旅程 2 · 林敏的第一个站点（闭环 C 的 M1 部分）→ `screens.md` §2–§3
1. 登录 Admin（M1 由运营者代林敏的默认租户操作；P5 起林敏在 Console 自助）。
2. 添加网站：站点名 → 域名 → 源站 → 绑定集群 → 预览将要发布的内容。
3. 域名页给出 CNAME/接入提示；源站页显示健康检查。
4. 站点证书：上传证书（私钥只写不读）。
5. **Climax**：点「发布」→ 发布抽屉校验通过 → 逐节点进度 → 「已全部生效 · 3/3」；林敏访问域名第二次请求看到缓存命中提示（日志/统计中可见）。

### 旅程 3 · 林敏让源站认出真实访客 IP（闭环 E）→ `screens.md` §4
1. 进入站点 → 网络设置 → 真实 IP 传递；页面顶部的方向示意图明确「LingEdge → 您的源站」。
2. 打开「自定义 Header」，输入 `Ling-Client-IP`；输入过程中实时校验（合法/保留名/长度）。
3. 保存 → 「已保存，未发布」琥珀状态出现；页内「源站 Nginx 配置指引」随 Header 名与**真实出口 IP 清单**自动生成。
4. 发布 → 「发布中 · 已生效 1/3 …」 → 「已全部生效 · 3/3」。
5. 林敏把指引片段复制到源站 Nginx，重载。
6. **Climax**：在「调试」面板点「发送测试请求」，看到「节点识别到的客户端 IP」与「最终传递的 Header」；她再用伪造 `Ling-Client-IP: 6.6.6.6` 的请求测试，源站日志里仍是真实 IP。

### 旅程 4 · 林敏为 `/old/*` 加重定向并回滚（闭环 D）→ `screens.md` §5–§6
1. 规则管理 → 新建规则：类型「重定向」，条件 `Path starts_with /old/`，动作「301 → /new/」，优先级可见。
2. 编辑器内实时校验；保存 → 规则行出现「未发布」圆点，站点发布条变琥珀。
3. 发布 → 抽屉显示变更摘要与校验 → 灰度「先 1 个节点」→ 观察规则命中数 → 扩大到全部。
4. 命中统计出现，林敏发现误伤了 `/old-faq/`。
5. **Climax**：在部署记录点「回滚到 v126」→ 抽屉显示反向差异 → 确认 → 「已回滚至 v126 · 3/3 生效」，命中统计停止增长。

### 旅程 5 · 陈工注册一个新节点（闭环 A）→ `screens.md` §7
1. Admin → 节点管理 → 节点注册：选择目标节点记录，生成**一次性注册令牌**（前缀 `lenr1.`，绑定该节点与角色而非集群；明文只显示一次、带有效期，选项最短 1 小时）。
2. 页面显示两条命令：`lingedge install node` 与 `lingedge node enroll --token-file <令牌文件>`（令牌不进命令行参数、shell 历史与 `ps`；也可交互隐藏输入或经 stdin），并进入「等待节点连接」。
3. 陈工在节点机上执行；页面状态机依次点亮：等待连接 → 已连接（身份证书已签发）→ 首次心跳 → 配置已同步 → 在线。
4. **Climax**：节点出现在列表，显示 Agent 版本、出口 IP、生效配置版本；令牌被标记为已使用并失效。

### 旅程 6 · 周编辑更新首页并回滚（闭环 I，P2）→ `screens.md` §10
1. 官网运营 → 首页装修：打开草稿，调整 Hero 文案、拖动模块排序。
2. 点「预览」→ 受保护的预览链接，在新标签看到 SSR 渲染的草稿。
3. 「定时发布」设置明晨 9:00；到点生效（状态：**已排期** → 已发布；CMS 的「已排期」与站点配置的「已保存，未发布」是两个不同概念，不得共用「待发布」一词；排期引用校验失败时显示「排期失败」）。
4. 发现错误 → 版本抽屉选上一版 → 对比 → 回滚。
5. **Climax**：前台刷新，首页恢复上一版；版本列表新增一条「回滚自 v7」的记录。

### 旅程 7 · 陈工升级节点，遇到不可逆迁移（闭环 J）→ `cli-tui.md` §5
1. `lingedge update check` 列出可用版本与「含不可逆迁移」标记。
2. 选择升级 → TUI 显示红色警告：「不可简单回退二进制；回滚路径 = 恢复升级前备份 + 旧版本二进制；备份点之后的数据将丢失」。
3. **强制备份先行**，随后要求输入确认语。
4. **Climax**：升级后健康检查失败 → Tools 自动执行「恢复备份 + 旧二进制」→ 报告「已回滚，服务已恢复」。
