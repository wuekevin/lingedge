## 2. 设计原则（八条，所有页面据此评审）

1. **真实优先**：无数据 → 空态；未交付 → 不渲染；非真实 → 标「示意」。永不用假数据让界面「看起来完整」（NFR-1）。
2. **保存 ≠ 生效**：对会进入节点配置的对象，界面始终区分「已保存」「已发布」「已在 N/M 节点生效」。
3. **方向清晰**：真实 IP 传递（LingEdge→源站）与入站可信代理（前置代理→LingEdge）在导航、文案、图示上分开。
4. **危险可见**：不可逆、跨租户、影响面大的操作升级确认强度，并带审计提示。
5. **隔离在入口**：Admin/Console 分入口分构建；导航只是权限的呈现，真正隔离在服务端。
6. **运维友好**：错误必须回答「发生了什么 / 为什么 / 怎么办 / 系统状态」，并附 Request ID 或日志位置。
7. **终端是一等公民**：TUI 与 CLI 同等重要，交互与非交互等价，机器可读输出稳定。
8. **品牌克制**：渐变只用在品牌时刻；数据界面用语义色；任何状态不靠颜色单独表达。

## 4. 需要用户知晓的重大 UX 取舍

1. **M1 后台只有 9/17 个一级菜单**：为遵守「不渲染假页面」，智能调度/DNS/安全中心/四层/产品计费/工单通知/插件/官网运营在对应阶段交付前**整体不出现**；完整 IA 已冻结在 `ia.md`。
2. **官网 M1 可能没有「节点数 / 可用率」**：它们只允许来自真实数据，或标「示意」；编辑者不能手输数字，节点地图点数必须等于真实节点数，没有监控就不显示可用率。这会让早期官网「看起来没那么大」，但符合基线 §5.3/§1.3。
3. **发布以站点整体为单位**，且**部分失败不自动回滚已成功节点**：可预测、版本可解释；代价是没有「单条规则快速上线」，出现版本不一致时由运营者决定重试还是回滚。
4. **安装向导增加「一次性初始化令牌」**：多一步，但避免向导在建好管理员之前被任意网络访问者抢占。
5. **视觉色值为提议**（基线只给「深蓝科技风、蓝紫渐变」）：品牌主色、字体、渐变方向均可整体替换，只影响 `DESIGN.md` 与令牌文件。
6. **规则试算（模拟请求命中哪些规则）延后到 P2**：需要与节点行为一致的评估器，M1 只提供自然语言摘要与校验。

## 6. 交给下游的清单

**交给架构（`[ARCH]` 汇总）**
1. 能力清单接口：每个模块「已交付」状态 + 当前用户权限点 + 运行模式，驱动菜单（UX-1）。
2. 节点「实际生效版本」汇报与 N/M 汇总（UX-4；API 枚举到固定状态词的映射见 `docs/api/README.md` §7，租户部署状态 `queued/running/success/failed/canceled/rolled_back`，`paused` 仅平台可见）；租户见站点线性版本 `site_version`，集群 `seq` 仅平台可见；部署策略（部分失败是否自动回滚，UX-6）。
3. 约束元数据随接口返回：Header 名长度上限、保留名单、条件嵌套深度、正则复杂度上限（EXPERIENCE · 表单校验）。
4. 乐观并发：ETag/版本号与 **412 `resource.precondition_failed`** 语义（校验失败统一 400，不用 422；幂等键误用 422 例外，ADR-017）。
5. 受控「调试」任务类型（真实 IP 调试，UX-7，API 任务类型 `realip.debug`：引擎内纯函数模拟，不向源站发请求，节点由服务端选取）；节点出口 IP 清单与变更事件。
6. 稳定错误码体系（供 i18n 映射）+ Request ID 贯穿（NFR-21）。
7. 公共统计接口（官网实时/快照数据，聚合脱敏，UX-18）；内容模型 `data_source`、能力状态字段。
8. 一次性初始化令牌（UX-13）、节点注册令牌与主控证书指纹（UX-14）、主密钥备份材料（UX-13，ADR）。
