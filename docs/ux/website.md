# LingEdge 官网与官网 CMS 的 UX 设计

> 属于 `docs/ux/ux.md`。依据基线 §5（官网、CMS）、§2.3、§1.3；PRD FR-40…FR-46、D-3、D-8、R-12、R-13、NFR-27。
> 2026-11-16 依据架构评审修订：见 docs/bmad/architecture-revision-log.md。
> 视觉令牌见 `DESIGN.md`；全局状态/i18n/可访问性规范见 `EXPERIENCE.md`；CMS 首页装修线框见 `screens.md` §10。

## 1. 定位与原则

- **完整商业级品牌官网，不是着陆页**（基线 §5.1）：深蓝科技风 + 蓝紫渐变、企业级布局、响应式、深/浅主题、中英双语。
- **可信胜过华丽**：官网面对的是要把业务流量交给 LingEdge 的技术决策者。所有能力声明、数字、地图必须与真实产品状态一致（§3、§9）。
- **阶段一致**：M1 官网是**静态预渲染（SSG）**，由 Nginx 托管，无 Node.js 运行时依赖；P2 CMS 起默认 SSR（Nuxt on Node.js）并保留「发布触发重新生成静态」降级（D-8）。UX 上，两种形态对访客**无差异**；对编辑者的差异只体现在「发布后多久可见」的提示上。
- **运行模式感知**（D-3、FR-40、FR-46）：自用模式隐藏价格一级导航与注册入口；商业模式（P5）完整显示。
- **不渲染假页面**：尚无后端支持的入口（工单支持、Docs 未装时的 API 文档等）显示「即将提供」状态页或隐藏，不跳转到假页面（FR-40）。

## 3. 官网数据真实性规范（强制）

基线 §5.3 与 §1.3：**生产展示的节点数、可用率、性能指标必须来自真实数据，或明确标注为示意信息**。UX 把它变成**不可绕过的组件契约**，而不是「编辑者注意」。

### 3.1 数据展示状态（仅此三种，外加「无数据」）

| 状态 | 条件 | 呈现 | 样例（文案） |
|---|---|---|---|
| **实时（真实）** | 数据来自真实监控/节点注册表的**公开聚合接口**，且新鲜 | 数字 + 数据来源与时间的角标（可展开）：「实时 · 更新于 2026-11-16 14:03 UTC · 来源：LingEdge 节点注册表」 | 「全球 12 个在线节点」 |
| **快照（真实但非实时）** | 构建时（SSG）或缓存的真实数据，附明确时间戳 | 数字 + 「截至 2026-11-16 14:00（构建时快照）」 | 「截至 11 月 16 日：12 个节点」 |
| **示意** | 没有真实数据源，或用于说明性展示 | **强制** `illustrative-badge`「示意」+ 虚线边框/降低饱和度；`aria-label` 含「示意数据，非实际」；不得出现看似精确的数值（用图形而非数字，或写明「示例」） | 地图上的装饰性点阵 +「示意」 |
| （无数据） | 真实数据源不可达/为空 | **隐藏该模块或显示「暂无数据」**；**绝不回退成上次的数字或示例数字** | 「节点数据暂不可用」 |

### 3.2 规则

1. **数字组件必须声明数据源类型**：内容模型字段 `data_source ∈ {live, snapshot, illustrative}` 为必填，缺省视为构建错误（CI 阻断）。`live/snapshot` 必须绑定到具体的**数据源标识**（如 `public.nodes.online_count`）；`illustrative` 不得绑定数字。
2. **编辑者不能手输「实时」数字**：CMS 的数据模块只允许选择「数据来源」，不提供数值输入框（`screens.md` §10）。若要展示非真实数字，只能选「示意」，且角标无法移除。
3. **「全球节点地图」**：
   - 只在地图上画**真实存在**的节点位置（来自节点注册表的公开字段：城市级粒度，不暴露 IP、机房、运营商）；节点总数 = 地图点数，二者必须一致。
   - 无真实节点（如 M1 刚上线只有 1–2 个）也如实显示 1–2 个点，不用点阵凑「全球覆盖」；若数量过少导致地图空旷，页面改为「覆盖区域」文字说明，而不是造点。
   - 示意版地图必须带「示意」角标与说明「展示网络部署形态，不代表实际节点位置与数量」。
4. **可用率（%）**：只展示来自真实监控的数字，且**必须同时标出统计口径与窗口**（「过去 30 天 · 口径见状态页」）；没有 Status（P5）与足够监控数据时**不展示可用率**。PRD NFR-31：任何对外可用率数字均能追溯到真实监控数据源。**官网不出现「99.9%」之类的承诺性数字，除非该数字是 SLA 条款且已由用户定义**（D-2：目前不设数值 SLA）。
5. **性能指标（延迟、吞吐、命中率…）**：同样只能来自已发布的《性能基线报告》（NFR-30）并附报告日期、测试环境摘要与链接；没有报告则不展示。禁止出现「毫秒级」「秒开」「全球最快」等无依据比较性表述。
6. **规模类文案**（客户数、请求量、流量）：同上；无数据则不写。
7. **公共统计接口**（`/api/v1/public/...`）`[ARCH]`：只返回聚合、已脱敏、可缓存的数据；**发行产物（M1 SSG）不含构建时快照**：数据模块在 HTML 中为「暂无数据」占位，运行时由客户端拉取实时值覆盖（失败保持占位，而不是静默沿用旧值）；构建时快照（带时间戳）仅限运营者自建站点显式启用（架构 IMP-17：快照随同一份签名产物分发会显示别人的数字）。
8. **价格**只读 `plans`（FR-45）；官网表里没有价格输入框；套餐价格的货币、计费周期与币种明示；与结算价格不一致属缺陷。
9. **自检清单**（内容评审门槛）：页面上的每个数字都能回答「它来自哪里、什么时候、谁能验证」；任一无法回答 → 删除或标「示意」。

### 3.3 视觉
- 实时/快照：数字旁小字来源角标，悬停/点击展开详情；
- 示意：右上角 `illustrative-badge`（琥珀）+ 虚线轮廓；
- 暗/亮主题下角标对比度均 ≥ 4.5:1（DESIGN.md 已验证 `warning` 配对）。

## 5. 登录 / 注册 / 控制台入口规则（FR-46）

| 运行模式 | 登录 | 注册 | 「控制台」 | 备注 |
|---|---|---|---|---|
| **自用（默认，M1）** | 指向 Admin 登录入口 | **隐藏** | 指向 Admin | 官网导航不出现「注册」；价格类入口可隐藏 |
| **商业（P5）** | Console 登录 | Console 注册 | Console | 已登录访客的「登录」按钮变为「进入控制台」 |

- 入口链接由**运行模式与已安装组件**决定（Website 构建/渲染时读取系统设置），不硬编码；Console 未安装时「注册/控制台」隐藏而不是 404。
- 注册页本身属于 Console（P5），官网只提供入口与说明。

## 6. 官网 CMS 的运营体验（Admin「官网运营」，P2）

菜单与基线 §5.4 一致（15 项）：官网概览、首页装修、页面管理、产品管理、解决方案、套餐展示、新闻公告、博客文章、FAQ 管理、媒体资源、SEO 管理、顶部导航、Footer 管理、多语言内容、官网设置。

| 菜单 | UX 要点 |
|---|---|
| 官网概览 | 未发布内容数、已排期队列、最近发布/回滚、翻译完整度、**数据模块状态（哪些模块在使用示意数据）** |
| 首页装修 | 见 `screens.md` §10；块编辑 + SSR 预览 + 版本 |
| 页面管理 | 页面树（含模板类型）；每页状态：草稿/已修改未发布/已排期/已发布；版本与回滚 |
| 产品管理 / 解决方案 | 内容型编辑；**能力状态字段（已提供/规划中）为必选**，驱动前台徽标；选「已提供」需关联已交付能力标识 `[ARCH]`（防止文案超前于产品） |
| 套餐展示 | **只读展示 `plans`** + 展示层选项（顺序、推荐标记、是否显示）；无价格输入（FR-45）；自用模式整菜单隐藏 |
| 新闻公告 / 博客文章 | 富文本/Markdown 编辑；分类、标签、封面、发布时间（定时）、多语言；公告可置顶、设有效期 |
| FAQ 管理 | 问答条目、分类、排序（拖拽+键盘）、多语言 |
| 媒体资源 | 上传、尺寸与格式检查、替代文本（alt）必填提示、引用关系（被哪些页面使用，被引用时删除需 L3）、基于路径穿越/类型的安全校验 |
| SEO 管理 | 页面级 title/description/OG/canonical/`noindex`；站点级 sitemap 与 robots；预览搜索结果样式；长度提示 |
| 顶部导航 / Footer 管理 | 树形编辑 + 拖拽；链接目标校验（不得指向未发布页面）；多语言标签；**未交付功能入口自动灰显并阻止发布**（避免导航指向假页面） |
| 多语言内容 | 以「内容单元 × 语言」矩阵展示翻译完整度，批量定位缺失项 |
| 官网设置 | 站点名、Logo（与品牌设置同源）、默认语言、主题默认值、统计代码（审计）、预览链接时效 |

**通用 CMS 规则**
- 所有内容类型共享同一套**状态机与版本机制**（草稿 → 已修改未发布/已排期 → 已发布 → 回滚），状态词见 `screens.md` §10 表；
- 发布 = 创建不可变内容版本；回滚 = 以旧版本内容创建新版本并发布（历史不被改写）；
- SSR：发布后立即可见；SSG 降级模式：显示「正在重新生成静态页面（N/M）」进度与失败重试；
- 预览：受保护、限时、`noindex`；
- 定时发布到点前再校验引用（媒体/套餐/页面）；失败则不发布并通知，不静默失败；
- 编辑冲突：版本号冲突对话框；
- 审计：发布、回滚、定时、取消定时、删除均审计；富文本输出一律转义/净化（防 XSS，NFR-9）。

## 7. SEO、国际化与技术体验

- **SEO**：每页独立 title/description/OG；语义化标题层级；`hreflang` 中英互指；sitemap 与 robots；结构化数据（Organization、Product）仅在内容真实时输出；预览/草稿链接 `noindex`。
- **国际化**：`zh-CN`（默认）/`en`；URL 前缀 `/en/…`，中文无前缀 `[ASSUMPTION]`；首次访问依据 `Accept-Language` 推荐语言但**不强制跳转**；语言选择记忆；缺翻译回退策略见 `EXPERIENCE.md` · i18n；文案长度差异下布局不破坏。
- **性能与稳健**（体验层面）：首屏内容不依赖 JS 才可读（SSR/SSG 的意义）；图片带尺寸与懒加载；字体自托管子集；无阻塞第三方脚本（不依赖外部 CDN 字体/统计，离线/私有化友好）。
- **隐私**：不默认加载第三方跟踪；若启用统计代码须在官网设置中显式配置并可在法律页披露。`[ASSUMPTION]`

## 8. 主题与响应式

- 亮/暗主题跟随系统，可手动切换并记忆；**Hero 与 CTA 渐变区在两种主题下都保持深蓝基调**（品牌识别一致），内容区随主题。
- 断点同 `DESIGN.md`；移动端：导航抽屉、单列卡片、地图改为区域列表+简化图、表格式套餐对比改为纵向卡片。
- 触控目标 ≥44px；`prefers-reduced-motion` 下关闭 Hero 动画。

## 9. 能力声明规范（防止文案超前于产品）

官网所有「能力」文案必须映射到**能力状态**，状态来源于产品已交付事实（CMS 里为必选字段，见 §6）：

| 状态 | 前台标记 | 允许的措辞 |
|---|---|---|
| 已提供 | 无徽标或「已提供」 | 现在时、可操作的描述（「支持 URL 刷新」） |
| 规划中 | 「规划中」徽标 | 将来时（「计划提供」），**不得出现「支持」「已具备」** |
| 高级能力（HTTP/3、L2 缓存、DNSSEC、边缘计算） | **P6 前不出现**，或仅在路线图中以「评估中」出现 | 不得出现「已支持 HTTP/3」等（NFR-27：不得仅以握手成功宣称；须功能等价验证） |
